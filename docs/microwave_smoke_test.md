# 微波仪实机 Smoke Test 清单

本文用于 MKM-AH1E 环形聚焦单模微波化学合成仪接入 Heat 后的实验室实机确认。本文不是普通用户操作流程，也不是化学工艺建议。

## 电脑托管逻辑段验收

软件测试不等于以下硬件项目通过。先按现场 SOP 使用合适负载，确认门控、探头、通风、接地及停止方式；不要在正常反应中断电来测试服务故障。

- 网页默认 1 段，添加第 2 段，输入不同温度及保温时间。检查程序和取消启动均不写硬件；参数、模式、段数、连接变化后需重新检查。
- 在自动功率和手动功率下分别核对五个硬件段的写后、启动后读回及HMI实际生效方案。保护时间为“到温超时＋逻辑保温秒数＋60秒”；核对方案与起止段，若参数被重载、读回失败或实际目标不一致，不能通过验收，须补齐厂家协议。静态读回一致不能代替实际方案确认。
- 独立记录物料到温时刻和实际输出，确认电脑在目标 ±5℃ 内连续稳定15秒后开始普通保温计时；稳定期间越界须重置15秒窗口，保温期间温漂只提示记录、计时继续。保温完成发送停止且控制位、功率、电流均停止后才配置/启动第 2 段；最后一段结束保持停止。验证启动会按预期重新计时、长设备保温在电脑计时内不会结束/跳到旧目标，记录段间停机对工艺的影响。网页逻辑段号与硬件当前段号不同，不能混用。
- 在受控条件下验证到温超时、运行故障/读取失败、配置失败、保温中停止及停机失败：不启动下一逻辑段，失败保留恢复锁，未确认停机不得放行实验。验证停止配置中的程序不会在配置返回后启动，原始停止和全局急停也禁止后续段。
- 页面刷新/关闭后后端继续监督；模拟服务异常退出只在实验室批准的条件下进行，验证记录中断、无自动续跑、原始停止后人工解除及旧请求不重放。服务失联会失去电脑监督，设备自身长计时不能保证立即停止或整个程序自主结束；记录独立联锁/现场停机措施。
- 正常关闭服务确认先等待托管停机，再释放连接。托管程序没有暂停/继续入口，不把页面停止按钮返回成功代替物理输出停止确认。

## 引导式批次五段覆盖验收

- 在受控测试条件下核对HMI方案及执行范围（含第4段），启动新建引导批次；五段均为本组目标，保护时长均为“到温超时向上取整秒＋本组保温秒数＋60秒”。分别核对写后、启动后实读和本机实际执行参数。
- 以80℃、保温10分钟、到温超时600秒为例，五段均为80℃、21分钟。电脑在80±5℃连续稳定15秒后计时10分钟；稳定阶段越界或实际暂停须重置15秒，稳定等待包含在600秒到温超时内。保温开始后温漂只提示和记录，普通计时不暂停或清零，完成后显式停机，不等待21分钟设备计时结束。记录真实温度偏离、计时、实际输出和段号，确认实际工艺是否接受这一计时方式。
- 两组不同反应温度时确认下一组重新覆盖全部五段；配置失败、提前退出控制或读取故障时应失败并停机，不进入收集或下一组。不得为通过测试绕过现有故障监督。

- 将Heat运行JSON中的配置实读、启动前后快照、控制字/段号/计时变化及STOP来源，与HMI报警、历史及USB导出逐时对照。检查温度来源切换，确认浮点字序与整数温度换算；保留原始日志，不修改历史结果。

- 反应瓶非空载，光纤探头已没入物料。

- 控制字 stop 写入、真实启动、真实停止和故障响应符合实验室预期。

## 当前控制开放与人工确认边界

按 2026-06-20 用户确认，Heat 当前允许像加热器/蠕动泵一样从前端按钮和 YAML 自动实验控制微波仪。当前配置字段默认应为：

```yaml
allow_experiment_control: true
allow_real_hardware_writes: true
enable_control_writes: true
```

含义：

- 这些字段保留用于兼容配置和状态展示；当前不再作为手动 REST/前端或 YAML 自动控制的阻断门。
- 前端按钮和 YAML 自动实验可以调用 configure/start/stop。
- 页面加载、WebSocket 连接/断开和状态刷新仍不得触发任何写入。
- 设备返回 `False`、异常或 timeout 必须记录为失败。

软件开放不代表实验室安全确认。真实启动、门控联锁、负载安全、故障响应、状态枚举和 stop 语义仍必须由现场人员按本文记录。

## 0. 准备检查

实验室人工确认：

- [ ] 设备型号与说明书一致。
- [ ] DB9 接线已确认：3=485A，8=485B。
- [ ] 设备 AC220V / 50Hz 供电、接地和急停/断电手段可靠。
- [ ] 炉门关闭且联锁正常。
- [ ] 设备四周散热空间大于 30 cm，现场通风和环境符合说明书。
- [ ] 反应瓶非空载；弱吸波或极少量物料不作为安全负载。
- [ ] 光纤探头已没入物料。
- [ ] 现场有人全程看护。
- [ ] 当前配置已复核为 `allow_experiment_control=true`、`allow_real_hardware_writes=true` 和 `enable_control_writes=true`，并确认现场允许本次控制。

软件检查：

- [ ] 后端可启动。
- [ ] `config/system_config.yaml` 中目标设备串口号、站号和控制开放字段已复核。
- [ ] 前端页面已更新到包含微波仪控制和仪表盘的版本。

## 1. 只读连接

目的：确认连接和只读状态不会启动微波。

步骤：

1. 启动后端。
2. 在 `/control` 页面连接 `microwave1`。
3. 刷新状态或调用 `GET /api/microwave/microwave1/data`。
4. 观察 `/` 仪表盘的微波仪卡片。

验收：

- [ ] 未发生微波启动。
- [ ] 状态可读，或失败原因明确。
- [ ] payload 包含 `device_id`、`connection_port`、`running`、`control_word`、`control_active`、`output_active`、`stop_confirmed`、`status_confirmed`、`material_temperature`、`power_percent`、`current`、`runtime_seconds`、`fault_code` 和 `current_mode_code`。
- [ ] `control_active` 只解释协议声明可读的 40151 启动位；状态不可读时 `status_confirmed` 不得显示为已确认停止。
- [ ] `fault_code` 只按原始值记录，不解释未确认 bit。

## 2. 地址基准确认

目的：确认 `40001 -> 0` 的 PDU 地址换算正确。

仅在实验室确认现场安全后执行：

1. 在不启动微波、不写控制字 `40151` 的前提下写入一个安全参数，例如手动段 1 的参数。
2. 读回同一寄存器或通过设备 HMI 复核。
3. 记录写入值、读回值和设备显示。

验收：

- [ ] 写入未启动微波。
- [ ] 读回或 HMI 显示与写入一致。
- [ ] 地址换算未出现一位偏移。
- [ ] 前端显示的目标设备串口与当前配置和现场身份一致（配置 fallback 为 COM6；指纹解析后的实际端口可能不同），并在写入前要求明确确认。
- [ ] 普通配置写入本身没有触发 start/stop 或控制字 `40151`。

## 3. 停止控制字验证

目的：确认当前实现 `CONTROL_STOP = 0` 不会导致异常启动，并能形成实验室认可的停机语义。

仅在设备处于安全可停状态时执行：

1. 保持现场看护和可断电手段。
2. 执行页面停止或 `POST /api/microwave/microwave1/stop`。
3. 观察 HMI、状态 payload 和设备行为。

验收：

- [ ] stop 写入未导致异常启动。
- [ ] 40151 启动位清除，功率和电流在有界等待内归零，`stop_confirmed=true`。
- [ ] HMI 和物理输出确认设备停机或保持停止状态。
- [ ] 失败时 API/日志没有伪装成成功。
- [ ] 实验室确认 stop 写 `0` 是否可作为正式语义；如不能，记录厂家建议值。

## 4. 最小启动/停止验证

仅在 0-3 全部通过并获得实验室授权后执行。

实验室人工确认：

- [ ] 当前负载安全、非空载。
- [ ] 温度、功率和时间参数为实验室批准的最低风险参数。
- [ ] 现场有授权人员看护。
- [ ] 有立即停机和断电手段。

步骤：

1. 在 `/control` 页面配置最低风险参数。
2. 通过页面二次确认启动。
3. 立即执行停止。
4. 记录 API 返回、HMI 状态、仪表盘状态、日志和实际设备行为。

验收：

- [ ] start 返回成功时 40151 启动位已读回且 `fault_code=0`，HMI 和物理输出也确认设备确实进入运行。
- [ ] stop 返回成功时启动位已清除且功率/电流归零，HMI 和物理行为也确认设备确实停止。
- [ ] WebSocket 断开或页面刷新没有触发启动或停止。
- [ ] 日志没有把失败、超时或设备返回 `False` 记录成成功。

## 5. YAML 自动控制验证

仅在 0-4 全部通过并获得实验室授权后执行。

步骤：

1. 使用只包含结构验证和最低风险参数的 YAML；不要使用未经批准的化学配方。
2. 验证 `microwave.configure_*`、`microwave.start`、`microwave_temperature_reached` 或 `microwave_complete`、`microwave.stop`。
3. 手动触发 stop，确认等待可中断。
4. 记录实验日志、HMI 状态、仪表盘状态和实际设备行为。

验收：

- [ ] YAML 自动调用只作用于实验室批准的目标设备。
- [ ] configure/start/stop 的成功或失败与设备实际行为一致。
- [ ] wait timeout 会失败，不会静默继续。
- [ ] stop 能中断微波等待。
- [ ] 实验日志、设备实际行为和最终状态一致。
