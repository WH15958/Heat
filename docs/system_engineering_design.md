# Heat v1 工程连接层设计

适用对象：需要把前驱体加热装置、蠕动泵、管路、微波反应仪和样品收集真正连接起来的实验人员与开发者。

本文只细化 Heat v1 的工程连接层，不新增设备驱动、API、YAML 动作或自动微波控制能力。看不清或未实测的参数一律标为“待实测”或“待手册确认”。

## 2. 系统拓扑

v1 的工程链路按下面的顺序理解：

```text
前驱体储液/加热 -> 蠕动泵通道 -> 长管路 -> 微波入口/反应区 -> 出口 -> 样品/废液收集
```

推荐把每条液路拆成四段记录：

| 管段 | 起点 | 终点 | 关键参数 | 确认状态 |
| --- | --- | --- | --- | --- |
| 吸液段 | 前驱体瓶/清洗液瓶 | 蠕动泵入口 | 长度、内径、是否浸没、是否吸空 | 待实测 |
| 泵管段 | 蠕动泵入口 | 蠕动泵出口 | 泵管型号、压紧状态、老化状态 | 待实测 |
| 输送段 | 蠕动泵出口 | 微波入口前 | 长管路死体积、气泡、保温、接头 | 待实测 |
| 反应/出口段 | 微波入口 | 样品/废液收集 | 微波允许压力、出口背压、收集方式 | 待手册确认/待实测 |

如果后续确认微反应器有三个入口，v1 优先使用：

```text
通道 1 -> 前驱体 A -> 微波入口 A
通道 2 -> 前驱体 B -> 微波入口 B
通道 3 -> 清洗液/载液 -> 微波入口 C
通道 4 -> 备用、稀释液或后续功能
```

不要在 v1 默认增加上游选择阀。只有在入口数量不足、清洗策略无法满足、或实验室确认需要自动换液时，再评估上游阀。

## 3. 工程参数表

每次搭建或改管路后，应至少记录下表。没有实测值时不要填猜测值。

| 参数 | 说明 | 示例 | 确认状态 |
| --- | --- | --- | --- |
| `line_id` | 液路编号 | `A`、`B`、`clean` | 待填写 |
| `pump_device_id` | Heat 中的泵 ID | `pump1` | 待确认 |
| `pump_channel` | 蠕动泵通道 | `1`-`4` | 待确认 |
| `fluid_role` | 液体角色 | 前驱体 A、前驱体 B、清洗液、载液 | 待确认 |
| `fluid_name` | 实际液体名称 | OA/OAm/ODE 体系等 | 待实验室确认 |
| `target_flow_ml_min` | 目标流量 | `5.0 mL/min` | 待实验设计确认 |
| `calibrated_flow_ml_min` | 真实标定流量 | 称重换算得到 | 待实测 |
| `target_dispense_ml` | 目标输送体积 | `15.0 mL` | 待实验设计确认 |
| `tube_model` | 泵管型号 | 查 `docs/device_materials/多通道蠕动泵MODBUS通信协议.md` 表 1；例如泵头 5 下 `11=1.52×0.86`、`13=2.79×0.86` | 待实验室按实物/泵屏幕确认 |
| `tube_inner_diameter_mm` | 管路内径 | 例如 `1.0 mm` | 待实测 |
| `tube_length_cm` | 该段管长 | 例如 `200 cm` | 待实测 |
| `dead_volume_ml` | 死体积 | 按公式或实测 | 待实测 |
| `precursor_temperature_c` | 前驱体温度 | 例如 `80 C` | 待实验设计确认 |
| `destination` | 液路目的地 | 废液、微波入口、样品瓶 | 待确认 |
| `material` | 管路/接头材料 | PTFE、PFA、PEEK、硅胶等 | 待确认 |
| `compatibility_status` | 溶剂/温度兼容性 | 已确认/待确认/禁止 | 待实验室确认 |

死体积估算公式：

```text
V = pi * (ID / 2)^2 * L
```

其中 `ID` 为管路内径，`L` 为管路长度。单位换算后得到 mL。长管路的死体积必须计入预灌和清洗，不应直接当作进入微波反应区的有效投料。

## 4. 流量与定量标定

蠕动泵屏幕上的定量值通常来自：

```text
输送体积 = 标定流量 * 运行时间
```

或更底层：

```text
输送体积 = 每转排量 * 电机转数
```

这只是泵端计算。对于 Heat v1：

```text
泵屏幕显示的输送体积 != 微波入口实际收到的目标溶液体积
```

必须至少做三层标定。

| 标定层级 | 接法 | 目的 | 判定 |
| --- | --- | --- | --- |
| 泵出口标定 | 泵出口直接收集 | 确认泵和泵管本身流量 | 记录平均流量与重复性 |
| 长管路末端标定 | 接入真实输送管路，在微波入口前收集 | 确认长管路、气泡、管路弹性影响 | 记录到达延迟和稳定流量 |
| 系统标定 | 接入微波入口/出口，在出口或安全收集端收集 | 确认背压、入口、反应器路径影响 | 需实验室确认安全后执行 |

推荐标定步骤：

1. 选择低风险液体，优先用水或实验室确认安全的替代溶剂。
2. 安装与真实实验相同的泵管、管路、接头和高度差。
3. 排尽气泡，使液体稳定到达收集端。
4. 设定一个固定流量，例如 `5.0 mL/min`。
5. 运行固定时间，例如 `60 s`。
6. 收集液体并称重，按密度换算体积。
7. 重复至少 3 次，记录平均值和偏差。
8. 用真实标定流量计算后续运行时间。

计算关系：

```text
实际流量 Q = 实收体积 / 运行时间
运行时间 t = 目标体积 / Q
```

如果管路原先不是目标溶液，则泵送量应至少包含：

```text
泵送量 = 管路死体积 + 目标进入微波入口体积 + 安全余量
```

安全余量只用于预灌/排废，不应计入有效样品体积。

## 5. 固定输运 SOP

### 5.1 预检查

- 确认微波反应仪入口、出口、压力限制和允许管路材料已经由手册或实验室确认。
- 确认废液瓶、样品瓶和出口路径已连接。
- 确认泵通道、流向、泵管型号和管路编号与工程参数表一致。
- 确认前驱体、清洗液、载液不会与管路材料或接头发生不兼容。
- 确认当前操作不会让微波腔体内出现不允许的材料或连接方式。

### 5.2 前驱体预热与搅拌

- 按实验设计设置前驱体加热装置温度。
- 等待温度稳定并保持搅拌。
- 观察是否出现析晶、分层、气泡、沉积或颜色异常。
- 记录前驱体批次、温度、开始时间和操作者。

### 5.3 排气与预灌

- 将出口先接到废液端，不要直接接入有效样品收集。
- 低速启动对应泵通道，使液体填满吸液段、泵管段和输送段。
- 排尽可见气泡。
- 至少泵送 `管路死体积 + 安全余量` 后，才认为液路被目标溶液置换。

### 5.4 进入微波入口

- 实验室确认微波入口处于允许接液状态。
- 将管路切换到微波入口，或确认入口已连接且出口通向废液/样品路径。
- 使用标定后的流量和运行时间输送。
- 如果使用泵的定量模式，记录泵设定体积和真实工程标定依据。

### 5.5 反应、收集与记录

- 按微波仪 SOP 设置反应条件；Heat v1 不假设已自动控制微波仪。
- 将无效预灌段和清洗段排入废液。
- 只有达到稳定流动和正确目的地后的液体，才记录为有效样品。
- 记录 `run_id`、`sample_id`、液路、泵通道、标定流量、实际时间、样品瓶编号和异常。

### 5.6 清洗与停机

- 停止前驱体通道。
- 使用清洗液/载液通道冲洗至少 `相关死体积 + 安全余量`。
- 将清洗段排入废液。
- 清洗后确认管路无明显残留、析晶或堵塞。
- 停止泵和加热装置，并按实验室 SOP 处理废液。

## 6. 风险控制

| 风险 | 影响 | v1 控制方式 | 确认状态 |
| --- | --- | --- | --- |
| 气泡 | 流量不稳、微波入口进液不连续 | 预灌、低速排气、透明观察段 | 待实测 |
| 虹吸/回流 | 停泵后继续滴液或倒流污染 | 保持液面高度、必要时加止回/背压方案 | 待设计 |
| 背压变化 | 蠕动泵实际流量偏离标定 | 做系统标定，不只做泵出口标定 | 待实测 |
| 泵管弹性 | 定量延迟、停泵后释放 | 记录停泵后滴液，必要时修正排废量 | 待实测 |
| 前驱体析晶 | 堵管、浓度漂移、污染样品 | 保温、搅拌、过滤策略需实验室确认 | 待实验室确认 |
| 材料不兼容 | 溶胀、泄漏、污染 | 确认管路和接头材料；普通塑料阀谨慎使用 | 待实验室确认 |
| 微波压力限制 | 超压、泄漏、设备风险 | 必须查手册并做低风险测试 | 待手册确认 |
| 清洗残留 | 样品交叉污染 | 建立清洗体积和废液段记录 | 待实测 |
| 样品编号错误 | 数据不可追踪 | 使用 Heat `metadata -> sample_id -> samples.csv` 链路 | 已有软件链路 |

硬件相关风险不能只靠软件验证关闭。真实设备身份、接线、压力、SOP、安全授权和实机烟雾测试必须由用户/实验室确认。

## 7. Heat YAML 映射

Heat 当前已有泵和加热器动作，可用于记录和执行泵送步骤。不要在文档或 YAML 中发明不存在的动作。

已知相关动作和等待类型：

| 能力 | 当前可用方式 | 说明 |
| --- | --- | --- |
| 设置加热器温度 | `heater.set_temperature` | 用于 Heat 已接入的加热器，不代表照片中所有加热装置都已接入 |
| 启动/停止加热器 | `heater.start` / `heater.stop` | 仅限已配置设备 |
| 启动泵通道 | `pump.start` | 支持通道、流量、方向、模式、泵管型号等参数 |
| 停止泵 | `pump.stop` / `pump.stop_channel` | 用于停止整泵或指定通道 |
| 等待泵完成 | `pump_complete` | 用于等待泵动作完成 |

示例：流量模式预灌到废液。

```yaml
- id: prime_ch1_to_waste
  type: pump.start
  params:
    device_id: pump1
    channel: 1
    flow_rate: 5.0
    mode: FLOW_MODE
    tube_model: 13
    flow_unit: 1

- id: wait_prime
  type: wait
  params: {}
  wait:
    type: duration
    seconds: 60

- id: stop_ch1_after_prime
  type: pump.stop_channel
  params:
    device_id: pump1
    channel: 1
```

示例：使用定量定速模式输送目标体积。

```yaml
- id: dispense_ch1
  type: pump.start
  params:
    device_id: pump1
    channel: 1
    flow_rate: 5.0
    mode: QUANTITY_SPEED
    dispense_volume: 15.0
    volume_unit: 1
    tube_model: 13
    flow_unit: 1

- id: wait_dispense_ch1
  type: wait
  params: {}
  wait:
    type: pump_complete
    device_id: pump1
    channel: 1
```

这些 YAML 示例只表达 Heat 已有泵动作。微波仪设置、阀切换、样品瓶切换和真实安全确认仍按实验室 SOP 人工执行，除非后续明确接入并补齐驱动、API、测试和文档。

## 9. AI 与实验室责任边界

Codex/AI 可以：

- 维护本文档、SOP、参数表和 YAML 模板。
- 根据已确认参数计算死体积、预灌体积和运行时间。
- 检查 Heat YAML 是否只使用当前支持的动作。
- 协助整理标定记录和样品追踪字段。

用户/实验室必须确认：

- 真实设备型号、入口/出口、压力限制和接线。
- 管路、接头、阀、泵管对前驱体和清洗液的兼容性。
- 微波仪 SOP、安全授权、泄压和废液处理。
- 真实流量、回流、堵塞、气泡、停泵后滴液和清洗效果。
- 样品是否科学有效，是否可用于后续 planner 或表征反馈。
