# Heat 日常开发与运行选择

网页端和桌面端共用 `frontend/src/` 的 Vue 页面，以及 `src/web/`、`src/experiment/`、设备和协议代码。桌面版另有 `src/desktop/` 负责窗口、托盘、导入和后台进程管理。修改业务功能时先在源码中验证，再按需要验证桌面集成。

## 当前开发分支

用户于 2026-10-21 明确要求保留 `codex/desktop-app`：本阶段的网页、后端和桌面联调继续在该分支进行。开发尚未完成，不自动合并到 `master`、归档或删除本地及远程分支。推送任务分支用于同步源码，不表示已经发布或完成验收。

新建其它分支仍按 [AGENTS.md](../AGENTS.md#7-git-workflow) 取得批准；提交、推送按 [测试与合并流程](testing_and_merge_flow.md) 执行。

## 按场景选择入口

| 日常场景 | 推荐方式 | 如何看到修改 | 是否构建安装包 |
| --- | --- | --- | --- |
| 页面布局、文字、图表、编辑器和交互 | Vite 开发网页 | 保存前端源码后热更新；完成后运行相关测试和生产构建 | 通常不用 |
| API、实验编排、存储、设备控制代码 | 源码 Web 后台配合网页；先用隔离测试和假设备验证 | 正常退出旧后台后重新启动源码后台 | 通常不用 |
| 检查生产前端与后端的完整配合 | 构建前端后使用 `start_heat.bat` 或 `python run_server.py` | 前端重新构建并刷新；后端修改后正常重启 | 不用 |
| 托盘、窗口、退出、首次导入或进程通信 | 源码桌面入口及桌面专项测试 | 前端先构建；正常退出旧桌面和后台，再启动源码桌面 | 涉及冻结路径、依赖或安装流程时按需提前构建验证 |
| 实验室日常运行及现场验收 | 选择已安装桌面版或已验证的源码 Web 版本 | 核对所选版本及其配置、配方和数据目录 | 使用既有版本无需构建 |
| 调整配置、实验 YAML 或录入实验结果 | 在所选运行方式对应的工作区操作 | 按现有页面及配置加载流程生效；配置是否需重启取决于对应功能 | 数据变化本身不用构建；格式或执行代码变化需验证 |
| 一批修复已稳定，准备更新安装版 | 按桌面发行流程生成并核验新版本 | 覆盖安装后才在已安装程序中生效 | 集中构建一次 |

软件验证使用独立临时数据和模拟设备；仅打开 `?demo=1`、更换端口或不点击启动，都不能代替设备与数据隔离。实机控制及停止结果继续由实验室确认。

## 网页端修改与测试

以下命令从项目根目录执行，先激活已有 Python 3.10 开发环境，并准备前端依赖。依赖安装要求见 [README](../README.md#快速开始)。开始联调前，正常退出当前占用 8000 的 Heat 后台，确认将使用的配置和数据目录；自动化软件验证仍使用隔离环境。

需要真实 API 联调时，在终端一启动源码后台：

```powershell
python run_server.py
```

在终端二启动前端开发服务器：

```powershell
npm --prefix frontend run dev
```

打开 Vite 终端显示的地址，通常为 `http://localhost:5173`。页面保存后热更新；`/api` 和 `/ws` 由 Vite 代理到本机 8000 后台。前端开发服务器本身不包含模拟后台：若 8000 是真实设备后台，开发页面也能访问真实控制接口。纯页面调试可先不启动后台，接口与状态显示则需要对应的模拟或联调环境。

`run_server.py` 当前绑定 `0.0.0.0:8000`，没有后端自动重载。后端修改后，先停止活动实验并确认停机，在后台终端用 `Ctrl+C` 正常结束，再重新启动。连接硬件时不要通过自动重载反复重建后台。前端 Vite 的 `Ctrl+C` 只结束开发页面服务，不结束 Python 后台。

完成前端修改后执行相关行为测试，并检查生产构建：

```powershell
npm --prefix frontend run build -- --mode production
```

构建结果写入被 Git 忽略的 `src/web/static/`。8000 空闲时，`start_heat.bat` 会启动源码 Web 后台并打开 `http://127.0.0.1:8000`；它使用构建后的页面，没有 Vite 热更新。若 8000 已有就绪的 Heat，脚本会直接打开该服务，不核对它来自源码还是安装版，因此不能靠双击脚本确认已切换版本或数据目录。已运行且确认属于本次源码的后台无需再启动第二份；刷新页面即可检查新静态资源，后端代码修改仍须正常重启。

Python、YAML、设备及存储变更按 [验证矩阵](testing_and_merge_flow.md#101-按变更类型选择验证) 选择检查，不能仅凭页面显示正常判定停止或保存成功。前端构建生成的两份声明先比较内容和换行，再决定是否纳入提交。

## 桌面功能的开发验证

先正常退出已安装的 Heat 及原 Web 后台，确认 8000 已空出。前端已有生产构建、开发环境具备桌面依赖后，可从项目根目录运行：

```powershell
python -m src.desktop.main
```

源码桌面使用当前源码和 `src/web/static/`，无需每次构建安装包。相关测试入口、依赖与发行验收见 [桌面版说明](desktop_app.md)。检查托盘显示、关闭收起、明确退出、失败保留与重试时，应同时观察桌面和后台日志。

注意：源码桌面默认也使用当前用户的 `%LOCALAPPDATA%\Heat`，与已安装程序共用该用户资料位置。它不会因从仓库启动就获得测试数据；仅设置 `HEAT_DATA_DIR` 也不能隔离整个桌面宿主，后台会按桌面资料位置指定工作区。软件自动化优先使用现有临时目录与假设备测试；需要界面隔离验证时，先准备独立资料及模拟后台方案。

## 代码版本与数据位置

| 运行方式 | 使用的代码与页面 | 默认业务数据 |
| --- | --- | --- |
| 源码 Web／Vite 联调 | 当前分支源码；Vite 直接读取前端源码，8000 页面读取生产构建 | 未设置 `HEAT_DATA_DIR` 时沿用原仓库路径行为，命令从项目根目录执行 |
| 源码桌面 | 当前分支源码与生产前端资源 | `%LOCALAPPDATA%\Heat\workspace` |
| 已安装桌面 | 上次安装时冻结的代码、依赖和页面 | `%LOCALAPPDATA%\Heat\workspace` |

原项目与桌面工作区是首次导入时复制的两份业务数据，此后不自动同步配置、YAML、历史或恢复记录。需要转移时，先正常停止相关后台、完整备份并核对关联，不能用单文件覆盖或重新导入绕过非空工作区保护。浏览器草稿按来源保存，Vite、源码 Web 和桌面 WebView 的草稿不应视为自动同步。

Web 与桌面后台都使用 8000，日常选择一个后台运行。启动网页开发联调前先正常退出桌面后台，避免开发页面误连已安装的旧版或正在实验的后台；不要为绕过冲突而另开硬件控制进程。

修改源码、生产构建、Git 提交和推送均不会更新已安装程序。按 [项目上下文的构建约定](../context/PROJECT_CONTEXT.md#61-桌面安装包构建时机2026-10-21-用户约定)，积累一批稳定修复后由 Codex 判断集中构建时机；安装替换及对外分发仍按已有授权执行。
