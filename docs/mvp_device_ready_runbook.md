# Heat 设备就位 MVP 运行手册

适用对象：设备已经基本就位，准备把 Heat 从单设备控制推进到水/替代液端到端闭环验证的实验人员与开发者。

本文是执行材料，不是化学配方。它把“热/泵/微波自动控制”和“人工管路、收集、SOP、安全确认”合在一个最小可复现流程里。软件只能证明控制链路、日志和样品追踪可用；真实设备身份、接线、负载、门控联锁、管路兼容性、废液处理和科学有效性必须由实验室确认。

---

## 1. MVP 边界

### 1.1 成功标准

完成一次低风险端到端运行，能证明下面链路可复现：

```text
设备连接 -> 液路预灌/标定 -> 自动实验 YAML -> 日志/历史记录 -> sample_id/samples.csv -> 人工确认记录
```

MVP 通过必须同时满足：

- `/control` 页面显示 `heater1`、`heater2`、`pump1`、`microwave1`，且 `connection_port` 与现场确认一致。
- 已完成单设备 smoke test；微波仪按 `docs/microwave_smoke_test.md` 完成实验室授权范围内的步骤。
- 每条参与 MVP 的液路有标定流量、死体积、预灌体积和废液策略。
- `experiments/mvp_water_loop_baseline.yaml` 可完整运行，且任何 skipped/timeout 都已人工复盘。
- `/history` 有对应 run，`samples.csv` 有对应 `sample_id`，人工记录能追溯样品瓶或废液路径。

### 1.2 本轮做什么

| 项目 | 本轮 MVP |
| --- | --- |
| 自动控制 | `heater1`、`heater2`、`pump1`、`microwave1` |
| 液体 | 水或实验室确认的低风险替代液 |
| 微波 | 最低风险负载和参数，禁止空载 |
| 管路切换 | 人工确认 |
| 收集切换 | 人工确认 |
| 阀门 | 不纳入本轮，不新增驱动/API/YAML 动作 |
| Campaign | 可记录 `run_id`/`sample_id`，不要求 planner 自动闭环 |

### 1.3 停止规则

出现任一情况，停止推进并记录：

- 串口身份不确定、`connection_port` 与现场不一致，或绑定显示未解析。
- 设备命令返回 `False`、timeout、异常，或日志把失败表现为成功。
- 微波负载、炉门、探头、通风、接地或现场看护未确认。
- 管路泄漏、堵塞、明显气泡无法排出、回流、虹吸或废液路径不可靠。
- 泵管型号、流向、通道、读回值和现场实物不一致。
- `experiments/mvp_water_loop_baseline.yaml` 运行中出现 skipped/timeout 且原因未关闭。

计算：

```text
实际流量 Q = 实收体积 / 运行时间
运行时间 t = 目标体积 / Q
预灌体积 = 管路死体积 + 安全余量
```

## 6. MVP YAML 使用方式

本轮默认 YAML：

- `experiments/mvp_water_loop_baseline.yaml`

执行前必须先完成：

- 本文第 3 节运行定义。
- 本文第 4 节设备串口确认。
- 本文第 5 节参与液路标定。
- `docs/microwave_smoke_test.md` 中实验室授权范围内的微波确认。

`mvp_water_loop_baseline.yaml` 是低风险基线，不是最终化学工艺。正式样品前，应把 YAML 中的流量、持续时间、目标温度和 metadata 改成已标定、已批准的值。

重要判定：Heat 可能把带 `on_error: skip` 的步骤记为完成后继续执行后续停机步骤。MVP 验收时，任何 skipped、timeout 或 read_failed 都不算通过，必须在第 7 节记录并关闭原因。
