## 手动操作与接口

2026-10-24 调试结果用于本机瓶位模式：1号瓶为机械原点0，12瓶按俯视顺时针编号。出液口固定，因此切换到下一瓶需要转台正向（俯视逆时针）移动12000脉冲；12到1也继续正向一格，累计坐标不清零。每次点击只发起一个动作，不自动连走后续瓶位。旧配置的 `bottle_count` 默认为0，不因升级而自动启用瓶位模式。

常用区显示后端确认的瓶号，提供“回原点”“下一瓶”和始终可见的停止按钮。高级操作默认折叠，展开不发送硬件指令。“回到1号瓶”使用负向机械回零，速度由 `bottle_home_speed` 指定（默认及本机1000脉冲/秒），与换瓶速度 `bottle_speed`（本机4000脉冲/秒）独立，使用 `bottle_home_timeout`（本机180秒）以覆盖约144秒的一圈寻找过程；高级回零仍遵守原 `action_timeout`。

开启瓶位模式时，配置校验要求 `bottle_home_timeout` 至少为 `bottle_count * pulses_per_bottle / bottle_home_speed + 5` 秒，`action_timeout` 至少为 `pulses_per_bottle / bottle_speed + 5` 秒，分别覆盖一圈回零和一格换瓶并保留至少5秒余量。本机对应下限为149秒和8秒；调整速度后须重新满足这两项校验。

瓶位信任只在常用回1号完成后建立，换瓶准确到位并稳定停止后才更新。启动、重连、控制器复位、读取异常、意外坐标变化、高级运动或显式停止后显示瓶号未知，须再次回1号。不会从累计坐标直接推断瓶号，也不会从旧记录恢复；连接、GET、WebSocket及页面生命周期不自动回零或换瓶。此前人工校验使用的累计坐标288129不会直接继承为新流程的可信1号。

高级控制初始速度为400脉冲/秒，允许整数范围400–40000；这不是RPM，也不覆盖常用换瓶配置。连续运行默认10秒，允许1–60秒；后台监督明确发起的动作，到时发送停止并核对状态。运动参数范围仅表示协议允许值，不表示转盘在全范围内可安全运行。

| `POST /api/turntable/{id}/command` 动作 | 请求字段 | 完成条件或限制 |
| --- | --- | --- |
| `home_bottle` | 无其他动作参数 | 配置瓶位模式并启用回零；负向寻找原点，观察到回零过程、坐标0及稳定停止后确认1号 |
| `next_bottle` | `expected_position`、`expected_bottle_token` | 当前瓶位可信且空闲；在设备锁内核对坐标和令牌，移动到当前坐标加一瓶间隔，准确到位并稳定停止后更新瓶号 |
| `run` | `direction: positive/negative`、`speed`、可选 `duration_seconds` | 观察到运行，到时停止并确认；提前停止或未观察到运行均失败 |
| `move_relative` | `steps`、`speed` | 相对脉冲为整数；计算后的目标也必须在坐标范围内；需启用 `position_encoding_verified` |
| `move_absolute` | `position`、`speed` | 整数目标范围 -9999999–99999999；需启用 `position_encoding_verified` |
| `home` | `direction`、`speed` | 需启用 `home_enabled`；必须观察到回零状态，随后停止于坐标 0 |
| `stop` | 无其他动作参数 | 发送 `0x02`，有界读取并确认停止状态及稳定坐标 |

相对位移字段自身也限制在 -9999999–99999999。有限定位和高级回零使用配置 `action_timeout`，默认60秒、范围1–3600秒；常用回1号单独使用 `bottle_home_timeout`。无关字段、布尔冒充数值、非整数速度/坐标及非法范围会被拒绝。回程序零复用 `move_absolute` 且 `position=0`，不等于机械回零，也不会建立瓶位信任。

瓶位命令由Web请求模型验证并在协调层翻译成既有机械回零或绝对定位指令；同步驱动及协议层不接收瓶位动作。`next_bottle` 使用最新快照中的 `expected_position` 和 `expected_bottle_token`，每次成功回1号或换瓶都生成新令牌，运动中及失效时撤销；即使回零后坐标又为0，旧请求也不能再次生效。这个前置检查在设备锁内完成，不重发运动、不绕过实验互斥或停止代次。

状态新增 `bottle_count`、`pulses_per_bottle`、可空的 `current_bottle/next_bottle/bottle_token`、`bottle_ready` 和 `bottle_error`；动作可带 `from_bottle/target_bottle`。客户端不自行从坐标计算瓶号，状态过期或无效时显示未知。瓶号只代表转台位置，不创建科学样品记录或标记瓶子为空。

其余接口为 `POST .../connect`、`POST .../disconnect`、`GET .../status`。未知 ID 返回 404，参数错误返回 422，占用或动作冲突返回 409，通信或停止确认失败返回 503；状态读取也可能返回 `read_ok=false` 的完整未知状态。命令返回 `{"success":true,"result":{...},"state":{...}}`，其中 `accepted` 仅表示请求已处理并发送，必须继续查看动作结果。`GET /api/devices` 和 WebSocket 实时包均增加 `turntables` 字典。

手动卡片在读数未知或超过 6 秒、忙碌、待停止确认时禁用新运动；仪表盘按 15 秒过期显示未知。已连接时停止仍可点击，请求期间显示“正在确认停止”，结果读回后更新，不把请求提交显示为停止成功。断开操作先停止并确认，失败保留连接。实验、批次、微波托管运行及待清理时禁止手动运动和断开；转盘运动或结果未确认也会阻止新实验启动。全局停止和正常退出清理包含转盘。

引导批次的持久化恢复/清理锁同样阻止手动写控制；记录不可读时返回503，不能当作没有待恢复批次。GET和STOP保留可用。REST、设备列表与WS状态包含 `state_session/state_revision`，控制卡片只接受较新快照，避免迟到响应覆盖新的失败或停止状态；`read_at=null` 的命令提交和失败响应也参与排序。

连接失败通过 `connection_error` 保留具体原因，GET/WS 刷新不会清除；成功连接或明确断开后清除。Windows 无法配置串口、串口无法打开、打开后控制器查询超时分别显示提示，原始异常保留在日志。`Cannot configure port` 是 Windows 设置串口参数失败，不能只因 Python 显示 `PermissionError` 就认定需要管理员权限。

连接失败后残留的打开句柄不视为有效连接；明确重连先释放旧资源，再打开并查询。首次连接失败且尚未发生运动时允许正常退出清理；资源释放失败则保留状态供重试。连接丢失或运动结果未知仍须确认停止，不能借重连或退出清除。

## 协议及确认边界

CL-01A 使用厂家二进制协议，通信为 115200、8N1，不使用 Modbus。发送帧为 `55 AA`、命令字、6 字节数据、`C3`，无文档确认的命令 ACK，因此串口写成功不能直接解释为设备执行成功；写入不自动重试。状态请求命令字为 `0x0C`，响应为无帧头的 8 字节，解析要求长度完整且无多余字节，未定义工作状态按读取失败处理。

当前发送实现中速度、位移字段使用小端字节序；状态坐标和速度字段按大端读取，坐标为有符号32位数。本机已按2026-10-24记录完成厂家报文和实机定位核验。新装置仍默认 `position_encoding_verified=false` 阻止相对/绝对定位和回程序零，不能只因模拟测试通过就启用；须对照厂家工具发送帧及控制器反馈核对正值、负值和字节位置，再验证小位移。速度反馈仅暴露 `speed_raw`，不显示为可信脉冲/秒或RPM。

输入低有效位为 bit2 正限位、bit3 原点、bit4 负限位、bit5 输入4。工作状态当前接受 `0x00` 复位、`0x01` 定位、`0x04` 手动运行、`0x08` 机械回零、`0x20` 停止。输入读回表示电平解释，不证明传感器安装、方向或电气极性正确。默认 `home_enabled=false`，须现场确认后启用；普通上电坐标 0 不会被记录为回零完成。

手册将 `0x02` 记为“暂停运行”，配套界面存在“停止”命名。Heat 的停止路径使用该命令，并要求连续两次停止状态及坐标不变才设置 `stop_confirmed=true`；这只是控制器反馈确认，不能证明机械急停、断能或取消内部程序的效果。尚未提供继续内部程序的按钮，也不在停止后自动续跑。定位完成同样要求停止状态、连续稳定读数及目标坐标一致；回零还必须观察到回零过程。

确认后若坐标再次变化，立即撤销停止确认和机械原点信任，阻止运动及实验启动，直到新的两次独立稳定停止读数形成。此自动恢复只解除坐标稳定性阻断，不会解除未知运动或失败STOP留下的保护。既有用户运行日志中一次动作完成，另一次停止读回 `0x10` 被拒绝；手册明确列其为“未定义”，当前仍按读取失败处理，不能推断为减速或停止。该日志不替代正式运动验收，本轮修复未再发送实机命令。

## 监督、故障和重启

同步驱动复用 `SerialPortManager`，内部没有后台线程、轮询或命令队列。Web 层的控制器锁串行协调设备访问；应用监督任务约每 0.2 秒检查已发起动作，串口响应时间可能延后检查和停止。HTTP 状态、WebSocket 使用同一读取协调键。停止代次撤销尚未发送的运动；取消 HTTP 请求不会取消已经开始的串口调用，也不会提前释放这次操作的保护。

读取失败、未知状态、控制器复位、目标不一致或动作超时均不包装为成功；活动动作失败后监督层尝试停止。停止未确认保留 `motion_blocked` 和资源状态，禁止新运动，等待明确重试。动作结果及错误写入业务日志，状态包含当前动作及瓶位反馈；瓶位不持久恢复，没有手动动作续跑机制。

页面关闭、刷新及 WebSocket 断连不控制转盘。**定时停止依赖后台进程、电脑和通信链路，进程崩溃、掉电或通信故障时软件不能保证停机。** 正常退出会尝试停止；异常退出后必须先现场确认设备状态，重启不会重放手动动作，`homed` 不从旧记录恢复。控制器状态返回坐标不能替代实际机械位置验收。
