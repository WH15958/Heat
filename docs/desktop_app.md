# Heat Windows 桌面版

桌面版使用独立窗口显示现有 Vue 界面，内置 Python 后台，设备控制仍由原 FastAPI、实验引擎和同步驱动执行。首版面向 Windows 11 x64；原有 `start_heat.bat` / `python run_server.py` 浏览器启动方式保留。

干净 Windows 11 x64 虚拟机和真实设备验收尚未完成。本文的验收清单是待执行项目，软件测试或安装包构建成功均不能代替这些验收。

## 安装与首次导入

1. 获取已完成构建及文件一致性核对的 `Heat-Setup-0.1.3-x64.exe`。安装目标默认为当前用户的 `%LOCALAPPDATA%\Programs\Heat`，使用者无需另装 Python、Node.js 或 npm。
2. 安装包包含 Microsoft WebView2 x64 离线安装程序；检测到已有运行时时直接使用，否则离线安装并检查结果。安装失败须先处理错误，不能跳过运行时检查。设备所需的 USB 串口驱动仍须按对应设备说明准备。
3. 首次启动前，在原 Web 服务窗口按 `Ctrl+C` 正常退出，等待实验停止、设备清理及记录保存完成。仅关闭浏览器不会停止原后端。桌面后台使用本机 `127.0.0.1:8000`；旧服务或其他程序占用 8000 时，应先解决占用，不能靠结束不明进程绕过检查。
4. 启动 Heat，按导入向导选择原项目根目录，其中必须包含有效的 `config/system_config.yaml`。源目录和桌面目标不能相同或互相包含。导入前建议另留完整备份；向导只读取原文件，不移动或改写原项目。
5. 导入成功后重新核对设备身份、串口指纹、USB 位置和通信参数，再按既有现场检查流程连接设备。新电脑或更换 USB 插口后，原绑定未必仍然有效。打开界面或完成导入不会启动实验。

安装包不携带开发机的仪器配置、历史记录或运行数据。首版通过导入现有工作区取得实际装置配置；安装包本身不是已配置完成的实验装置。

导入范围限定为配置、实验 YAML、Campaign、样品记录、注射泵程序登记、实验日志、批次检查点与完整方案、微波托管及普通 YAML 恢复记录，以及默认 `logs/`、`reports/`。源码、虚拟环境、运行中的进程锁和临时写入文件不复制。恢复记录属于必须保留的实验状态，不能把它们当作临时锁删除。

导入会暂存文件并核对大小、SHA-256 和源文件是否变化，成功后整体发布桌面工作区。只读源文件的副本会转为可写，原文件内容和属性保持原样。目标非空时不覆盖；校验、复制或配置检查失败时不标记初始化完成，只清理本次暂存目录。符号链接、Windows junction 和逃逸路径会被拒绝。

首版只支持配置中的 `logging.log_dir=logs`、`report.output_dir=reports`；自定义目录、绝对路径或上级目录引用会拒绝导入。遇到此情况应先备份，由维护人员整理目录与配置，再重新导入，不能直接忽略历史文件。

Chrome、Edge 等外部浏览器的 localStorage 不在迁移范围内。原浏览器中的未提交批次草稿、面板偏好不会自动带入桌面版；需要保留的输入应在迁移前自行记录。后端保存的实验历史和样品记录按上述清单导入。

## 窗口、托盘与退出

右上角关闭按钮将窗口收至系统托盘，后台和实验继续运行。通过托盘“显示窗口”重新打开；再次启动 Heat 会复用当前桌面实例。界面关闭、WebSocket 断开或界面进程异常退出，不触发实验启动、停止或自动恢复。

需要结束程序时，使用托盘“退出 Heat”并确认。退出请求会阻止新的实验启动和手动写入，停止活动实验、批次及托管程序，并确认设备清理和记录保存。成功后才退出后台。

停止返回失败、保存失败或等待超时时，会显示错误并保留后台；未确认停止的连接和恢复占用保留供处理或重试。此时仍可读取状态、显式停止、急停及按现有流程确认恢复，不能继续启动新实验。现场人员应先检查设备并按 SOP 停机，处理原因后再重试退出。不要用任务管理器强制结束代替这条退出路径。

停止未确认时，通用清理仍尽力停止其它设备，但保留连接供下次明确重试。存储故障排除后，再次退出会补写已结束运行中尚未保存的样品和日志；已成功保存的样品不重复追加，原运行编号、执行结果、步骤和结束时间保持不变。

后台异常退出时，桌面版不自动重启后台，也不续跑实验。先现场确认设备状态，再点击错误页“重新连接／启动后台”。重启后可能显示普通 YAML、批次或微波托管的恢复锁，须按页面提示确认设备已经停止；解除锁定仅允许后续操作，不重放动作，不把历史失败改为成功。

电脑睡眠、关机、掉电或通信故障仍可能使软件定时失去监督。托盘运行不能保证这些情况下设备自动停止，实验期间应保持控制电脑和后台运行并现场看护。

## 数据、备份与升级

所有位置均属于当前 Windows 用户：

| 内容 | 默认位置 |
| --- | --- |
| 安装程序文件 | `%LOCALAPPDATA%\Programs\Heat` |
| 配置、实验、历史和恢复记录 | `%LOCALAPPDATA%\Heat\workspace` |
| 首次导入清单与初始化标记 | `workspace\.heat-workspace.json` |
| WebView 草稿及页面偏好 | `%LOCALAPPDATA%\Heat\webview` |
| 桌面身份、进程信息与启动日志 | `%LOCALAPPDATA%\Heat\desktop` |
| 界面启动及导入错误日志 | `%LOCALAPPDATA%\Heat\desktop\desktop.log` |
| 后台早期错误日志 | `%LOCALAPPDATA%\Heat\desktop\backend.log` |
| 业务运行和设备日志 | `workspace\logs` |

备份前正常退出 Heat，再备份整个 `workspace`；它包含互相关联的历史、样品、方案和恢复记录。需要保留桌面本机草稿时，一并备份 WebView 资料目录。不要在服务运行中单独复制某个 JSON 或只复制 `samples.csv`，也不要手工删恢复记录来解除占用。桌面身份文件用于本机进程通信，不应放入发行包或对外提供。

升级和卸载前必须通过 Heat 的明确退出流程等待后台结束。安装器检测到界面或后台仍在运行时会拒绝继续，不自动强杀进程。升级替换安装目录中的程序文件，不重新导入或覆盖用户工作区；卸载保留 `%LOCALAPPDATA%\Heat` 下的数据。需要彻底清除数据时，应在正常退出并确认备份后由用户单独处理。

离线实验电脑使用带完整 WebView2 安装程序的安装包；无需在目标机在线下载 Python 或 npm 依赖。首次导入仍需要可访问的原工作区。离线安装成功与设备串口可用分别验收。

## 开发、构建与发布

日常网页修改、源码桌面验证、数据位置及分支保留约定见 [日常开发与运行选择](daily_development.md)。

源码入口为 `python -m src.desktop.main`，独立后台入口为 `python -m src.desktop.backend`。开发运行需安装桌面依赖并已有生产前端；后台仅在完成桌面工作区导入后启动。不要同时运行原 Web 后端和桌面后台。

桌面壳负责导入、窗口、托盘、单实例和后台状态；后台固定绑定 `127.0.0.1:8000`，单 worker。二者通过 Windows 私有命名管道交换有界 JSON 消息，使用当前用户资料目录中的身份密钥认证；不通过新增公开 HTTP 接口触发退出。REST 和 WebSocket 继续服务原业务界面，不随窗口生命周期操作硬件。

后台在导入业务模块前设置 `HEAT_DATA_DIR`，通过 `src/utils/runtime_paths.py` 锚定默认可写路径。未设置该变量的原 Web 启动保持原路径行为。报告和日志工具的显式目录参数继续按调用者指定的位置写入，可用于隔离测试或导出；默认目录仍使用桌面工作区。`src/web/static/` 属于只读安装资源，不能迁入用户工作区；开发测试仍可替换现有模块级路径常量。

构建机需准备 Python 3.10 x64、Node.js `^20.19.0 || >=22.12.0` 及 npm、Inno Setup 的 `ISCC.exe`，以及微软官方 Evergreen Standalone x64 WebView2 安装程序。Node 版本要求来自当前锁文件中的 Vite/Rolldown，本轮验证环境为 Node.js 24.21.0；安装目标机无需 Node.js。执行：

```powershell
.\scripts\build_desktop.ps1 `
  -Python 'C:\Path\To\Python310\python.exe' `
  -ISCC 'C:\Path\To\Inno Setup 6\ISCC.exe' `
  -WebView2Installer 'C:\Installers\MicrosoftEdgeWebView2RuntimeInstallerX64.exe'
```

脚本在 `output/desktop/venv` 创建独立 Python 3.10 x64 环境，安装桌面构建依赖，执行依赖检查、生产前端构建、图标生成、PyInstaller onedir 打包和 Inno Setup 编译。它不安装到原实验 Conda 环境。`-SkipFrontend`、`-SkipDependencyInstall` 只供已具备对应产物和依赖的重复构建使用，不跳过后续校验。

WebView2 输入须通过微软有效数字签名、产品信息、x64 文件名和完整离线包大小检查，网络 bootstrapper 会被拒绝。此检查针对随包的微软运行时，不代表 Heat 安装器已完成自身代码签名。

| 产物 | 位置 |
| --- | --- |
| 程序目录，含 `Heat.exe`、`HeatBackend.exe` 和共享依赖 | `output/desktop/dist/Heat` |
| 当前版本安装器 | `output/desktop/release/Heat-Setup-0.1.3-x64.exe` |
| 版本、依赖与 SHA-256 发行清单 | `output/desktop/release-manifest.json` |

发布检查按明确资源清单收集静态页面和代码依赖，拒绝夹带 `config/`、`data/`、`output/`、`logs/`、`reports/`、`experiments/` 等现场目录。不得通过打包整个工作树解决缺资源问题。构建产物保持在被 Git 忽略的 `output/`，不进入源码提交。

相关软件回归入口：

```powershell
python -m pytest tests/test_desktop_paths.py tests/test_desktop_migration.py tests/test_desktop_shutdown.py tests/test_desktop_host.py tests/test_desktop_packaging.py tests/test_desktop_persistence_retry.py -q
python tests/test_metadata.py
python -c "import src.web.app; import src.web.api.experiments; import src.web.api.ws"
```

桌面依赖、构建脚本或退出协调变更须按影响范围补软件检查；文档摘要变更只做内容和 diff 检查。完整分支、提交与推送规则仍遵循 [testing_and_merge_flow.md](testing_and_merge_flow.md)。

| 再次启动及离线历史查看 | 配置、草稿和历史保留，导出仍能关联完整批次和运行日志 |

## 真实设备验收边界

在已确认设备身份、接线、物料兼容和现场安全条件后，由实验室按现有 [MVP 验收清单](mvp_system_acceptance_checklist.md)、[微波实机测试](microwave_smoke_test.md) 和 [注射泵验收](syringe_pump_acceptance.md) 执行。桌面新增检查至少包括：

- 对照原 Web 方式验证连接、设备读数、最小实验、暂停/继续及停止；不因换成窗口而改变驱动协议和实验语义。
- 实验运行中收至托盘、重新打开界面，确认实际设备动作和计时保持预期；不能只看页面进度。
- 使用明确退出验证各设备停止及释放串口，核对物理输出、泵停止、微波功率/电流及相关日志；模拟失败时核对连接和恢复占用保留。
- 按现场 SOP 验证通信故障、后台异常和控制电脑运行中断的处理，再检查显式重启及人工解除锁定；不得用真实危险工况代替软件故障模拟。
