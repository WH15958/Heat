## 1. [P1] 急停等待普通手动请求释放全局锁后才开始执行

**位置：** `src/web/api/devices.py:23`、`:561`。

`protect_guided_devices()` 持有 `_source_lock` 并跨越 `yield`，因此锁覆盖手动接口的整个串口调用。`emergency_stop()` 又必须先获得同一把锁，随后才给引擎设置停止标志和调用 `dm.emergency_stop_all()`。

**触发：** 加热器连接、设置或启动请求仍在等待串口读回/重试，此时用户点击全局急停。急停既不能先取消后续实验步骤，也不能先停止其他设备，必须等该手动请求结束。引导批次启动的只读 preflight 同样在共享锁内，亦会占用此入口。

**复现：** 保持真实 `protect_guided_devices()` 依赖上下文打开，启动急停协程；确认设备管理器未收到任何急停调用。释放上下文后，急停才被调用。复现仅以受控等待模拟未完成请求，不声称具体实机延迟。

**建议：** 将“禁止新启动/取消待执行命令”的停止意图与慢速 I/O 锁区间分开；保持启动互斥，同时允许急停先发布停止意图。继续复用现有设备锁和 generation 机制，不绕开串口协调。增加“设备 A 正在慢读回，急停仍能先取消后续动作并处理其他设备”的 API 并发回归。

## 2. [P1] 普通实验停机未确认后，前端关闭停止重试入口

**位置：** `frontend/src/views/ExperimentPage.vue:56`、`:383`、`:596`；`src/web/api/experiments.py:281`。

引擎清理失败时会进入 `failed` 并保留 `cleanup_pending=True`，继续占用全局实验入口；底层 `engine.stop()` 支持重试。但进度 API 和推送没有提供清理状态，页面只在 `running/paused` 时启用“停止”，并在 `failed` 时停止轮询。

**触发：** 实验自然结束或用户停止时，泵第一次停止读回失败，之后通信恢复。页面显示失败，停止按钮禁用，新实验又被后端以占用拒绝；无法从原实验页面重试释放占用。

**复现：** 假泵第一次停止返回 `False`、第二次返回 `True`。首次结束后的真实进度响应为 `state=failed`，缺少 `cleanup_pending`；直接再次调用引擎停止成功。隔离运行真实 Vue 页面脚本后，确认该响应使“停止”禁用条件为真。

**建议：** REST/WS 暴露待清理状态；终态但待清理时明确显示“停止未确认”，保留重试停止与状态更新入口。现场安全处理仍遵循现有 SOP，不能将重试请求成功发送等同于物理停机。

## 3. [P2] 正常关闭服务没有结束普通实验与引导批次

**位置：** `src/web/app.py:172`、`:183`。

lifespan 退出仅等待微波托管程序停机，随后取消采样任务并调用设备管理器清理；没有遍历共享 `_engines` 对普通实验和引导批次设置停止标志、等待运行任务结束及记录终态。设备级清理不等于引擎停止或实验记录完成。

**触发：** 普通 YAML 正在长等待时使用正常退出（例如 Ctrl+C）。设备清理已经执行，普通引擎仍处于 `running`；事件循环退出时其任务可能直接被取消，无法通过 `finish_run()` 保存本次运行终态、日志和样品条目。引导批次也未经过其正常停止收尾流程。

**复现：** 注册真实的普通等待引擎，使用假设备运行实际 lifespan。退出 lifespan 后，`dm.cleanup()` 已调用，但 `_stop_flag=False`、引擎任务未结束、状态仍为 `running`、日志 `finish_run()` 未调用。复现脚本随后显式停止假引擎进行自身清理。

**建议：** 正常退出统一禁止全部引擎继续派发动作，等待所有类型运行的停止/持久化收尾，再释放设备；保留单个清理失败不阻止其他设备处理的行为。补充普通实验、引导批次、托管程序的退出测试。

## 4. [P2] 执行入口没有复用编辑器的完整参数校验

**位置：** `src/web/api/experiments.py:132`；`src/experiment/parser.py:109`；对照 `src/experiment/editor.py:52`。

保存/校验入口执行 `_check_params()` 等完整检查，文件执行入口却直接使用 `parse_experiment()`。基础加热器、蠕动泵和微波动作的部分必填参数只在编辑器验证，执行解析器并不统一拒绝。

**触发：** 用户按文档直接在 `experiments/` 添加 YAML：第一步 `heater.start` 合法，第二步 `heater.set_temperature` 缺少 `temperature`。编辑器明确认为文件无效，执行链却先启动加热器，到第二步才因缺少字段失败并清理。静态可发现的错误变成部分执行后的失败。

**复现：** 同一份 YAML 的 `validate_source()` 返回无效，而 `parse_experiment_content()` 返回两步；将解析结果交给真实引擎与假设备后，确认 `start_heater()` 已调用，随后实验失败。

**建议：** 保存与执行共享结构及动作参数验证，确保整份定义在任何硬件调用前通过；保留执行时针对当前连接、设备能力和占用的复查。

## 5. [P2] Campaign 表征与 Trial 更新不是同一个事务

**位置：** `src/campaigns/store.py:256`、`:258`。

`create_characterization()` 先保存 `characterizations.json`，再更新 `trials.json`。第二步发生磁盘/权限/文件占用错误时没有回滚或恢复日志，也没有请求防重放机制。

**触发：** 表征已写入，但 Trial 状态写入失败。请求报错，Trial 仍是旧状态；用户按失败提示重试后会生成第二条表征，污染历史数据。

**复现：** 临时存储内向 `update_trial()` 注入 `OSError`。失败后已有一条表征，Trial 仍为 `planned`；恢复写入并重试后有两条表征。

**建议：** 复用现有 recommendation 双文件事务的恢复思路，确保表征与 Trial 更新共同提交或共同回滚，并验证失败重试不会重复记录。

## 6. [P2] 历史删除在 samples.csv 更新失败时仍返回成功

**位置：** `src/experiment/experiment_logger.py:422`、`:424`、`:440`、`:446`；`src/science/sample_record.py:119`。

删除先移除 JSON 日志，再调用样品记录删除函数；后者捕获写入错误并返回 `0`，调用方忽略结果，单条删除仍返回 `True`、批量删除仍报告已删除数量。

**触发：** Windows 上 samples.csv 被其他应用占用，或原子替换遇到权限/磁盘故障。页面显示删除成功，CSV 仍含指向已不存在日志的样品记录。重试单条删除因 JSON 已不存在而失败，无法由原入口完成关联清理。

**复现：** 临时目录内建立一份 JSON 日志及一条样品记录，仅在删除 CSV 时令 `os.replace()` 抛出 `PermissionError`；确认删除返回 `True`、日志消失、CSV 行保留，随后重试返回 `False`。

**建议：** 区分“没有对应样品行”与“删除失败”，向 API 显式传播失败；采用可恢复的关联删除顺序或事务记录，允许缺少 JSON 时继续修复未完成的 CSV 删除。
