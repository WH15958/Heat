## 1. 系统启动

### 1.1 启动后端服务

```bash
conda activate heat
python run_server.py
```

默认访问地址：

- `http://localhost:8000`

Windows 也可双击项目根目录的 `start_heat.bat`：

- 优先使用项目 `.venv`，其次 `venv`；否则尝试激活 Conda 的 `heat` 环境，失败时检查 PATH 中的 Python。自定义位置的 Conda 若未被找到，可在 Anaconda Prompt 中运行脚本。
- 启动前检查 Python ≥ 3.10、后端依赖能否导入及 `src/web/static/index.html` 是否存在。缺少依赖或页面文件时会提示安装/构建命令，不自动安装。
- 已有服务时，只有确认 Heat 的 API 描述与前端页面可用才会打开浏览器；其他程序占用 8000 端口时会报错。连续双击不会重复启动同一项目的服务。
- 启动就绪检测使用 30 秒时间预算。若仍未就绪，将提示超时并保留服务窗口供排查；此时没有自动终止服务，应查看日志并用 `Ctrl+C` 正常退出。
- 服务前台运行，控制台输出同时追加到 `logs/launcher.log`，包括早期导入错误。失败后窗口保留错误信息。

服务运行时保留窗口。退出前先结束实验并确认设备停止，再在服务窗口按 `Ctrl+C`，等待关闭日志和设备清理完成；不要用关闭窗口或强制结束进程代替正常退出。关闭浏览器不会停止服务或设备。启动器只检查 Web 服务就绪，不代表设备已经连接或安全停止。

### 1.2 前端更新后的处理

如果有人修改了前端代码，需要重新构建：

```bash
cd frontend
npm run build
```

构建产物会写入 `src/web/static/`。如果页面看起来没更新，先按 `Ctrl+Shift+R` 强制刷新浏览器。

## 2. 页面与操作

### 2.1 页面入口

系统包含 5 个主要页面：

| 页面 | 路径 | 作用 |
|------|------|------|
| 实时仪表盘 | `/` | 查看实时温度、泵状态、微波仪状态与推送数据 |
| 设备控制 | `/control` | 连接设备、控制加热器、泵与微波仪 |
| 实验页面 | `/experiment` | 选择 YAML 实验、启动、暂停、恢复、停止 |
| 实验编排 | `/experiment/editor` | 图形或 YAML 编辑、校验与保存实验 |
| 智能实验 | `/campaigns` | 管理 Campaign、Trial、人工推荐与离线表征结果 |
| 历史记录 | `/history` | 查看实验历史记录和已保存日志 |

智能实验页面使用 `/api/campaigns` 接口，完整人工闭环流程见 [campaign_workflow.md](campaign_workflow.md)。
左侧 Campaign 列表只显示序号和名称；点击名称可在弹窗查看材料体系、目标指标、参数、状态及备注，点击“进入 Campaign”才切换右侧工作区。新建表单位于左栏“新建”弹窗；打开或关闭详情不会生成 Trial，也不会控制设备。

### 页面布局与导航

界面采用蓝白主题，顶部显示 HEAT 标志和当前页面，左侧导航保留上述五个入口。窗口宽度小于 1200px 时侧栏缩为图标导航；小于 768px 时可通过顶部“展开导航”按钮切换页面。

设备控制页在宽屏下左侧按设备类型显示“加热器、蠕动泵、微波仪、注射泵”，右侧显示所选类型的控制面板；窄屏下设备列表位于面板上方。选择“加热器”或“注射泵”时，两台设备在右侧上下排列，分别独立连接、设置和控制。左栏显示设备数量和连接概况，具体串口在各自面板内核对。控制面板宽度和起始位置统一，切换时保留已填写的参数和标签页选择，不触发连接或控制命令。设备卡片中的串口、绑定身份、连接状态和故障信息仍需逐项核对，插画上的屏幕数字仅为装饰，不是设备读数。泵通道保留模式与全部参数，以及可展开的“预灌估算”。“紧急停止所有设备”位于设备列表上方，使用原有确认和停止结果反馈流程。

每次进入实时仪表盘或设备控制页，默认选择列表中的第一个设备分组（当前为加热器），不沿用上次进入页面时的选择；设备列表的请求返回顺序不会改变默认分组。

实时仪表盘的加热器、蠕动泵、微波仪和注射泵面板标题使用与设备控制页相同的设备插画；注射泵插画参照 MSP1-CX 说明书中的立式设备外形。离线时也保留插画，连接状态和读数仍以旁边的状态信息为准。

### 2.2 设备连接

蠕动泵连接时会初始化启用的通道。任一初始化命令失败或抛出异常都会立即终止初始化并报告“连接异常”，不会继续配置后续通道或允许启动；串口保留供重试安全停止。确认停止并成功断开后，才可重新连接。串口打开或自动重开不等于设备通信与初始化成功。

设备控制页的停止按钮（含通道停止、全部通道停止及全局紧急停止）统一使用浅红底、红色描边样式。

在设备控制页面中：

1. 找到目标设备
2. 点击“连接”
3. 连接成功后状态会更新
4. 控制卡片会显示注册串口，当前迁移配置为加热器 1 `COM14`、加热器 2 `COM15`、蠕动泵 `COM3`、微波仪 `COM6`。实际端口以指纹绑定解析结果为准；两台加热器按 USB 位置绑定，更换电脑或插口后应重新核对设备身份和绑定位置。

设备参数可以在连接前预填。写入、启动或停止按钮不再仅靠前端置灰来拦截；点击后会先做连接/状态检查，必要时弹出设备检查确认。未连接、后端返回 `False`、超时或状态异常都会显示为失败。

普通 YAML、引导批次及微波托管程序运行、暂停或停机清理未确认期间，手动写入与断开会被拒绝。状态读取仍可用；手动停止会同时要求活动实验停止，阻止后续步骤继续执行。

普通 YAML 也会保存独立的运行恢复记录，即使关闭“保存日志”也不能关闭这份记录。服务异常退出后，实验页会显示“普通实验锁定”；系统不会续跑、重放动作或因页面刷新而停机。锁定会阻止普通实验、引导批次、微波托管及手动写控制。现场确认相关设备停止后，点击“现场确认停止后解除锁定”；当前服务仍有未停止的运行时须先停止，停止或确认保存失败则保留锁定。解除只允许重新操作，历史失败结果不改成成功。恢复记录不可读时禁止启动，应检查存储，不能通过删除记录规避确认。

实时连接断开或连续 6 秒未收到实时数据时，界面将读数视为未知；网络重新连通后须等新数据，不沿用断线前状态。连接状态不等于数据有效。加热器区分运行、停止、保持及未知；蠕动泵暂停不显示为停止。

点击“断开”时，页面会持续显示正在安全停止并断开的提示；后端会先取消尚未执行的启动请求并确认对应设备已停止，只有 stop 成功后才释放串口。如果 stop 返回 `False` 或抛出异常，系统会保留连接并显示具体失败原因，此时必须按现场 SOP 停机或使用物理急停，不能把“断开”当作急停手段。

设备命令分为三个层次：协议写入被接受、可读寄存器与请求一致、现场物理行为与状态一致。Heat 只有在适用的可读状态确认后才把启停显示为成功；物理转动、加热输出、微波门控和断电效果仍必须由现场人员确认。MVP 总体验收记录见 [mvp_system_acceptance_checklist.md](mvp_system_acceptance_checklist.md)。

连接按钮在请求期间显示“连接中”，连接失败时会在设备卡片内保留错误信息，同时在页面顶部短暂提示；再次尝试连接会清除上次错误，连接成功后显示已连接。操作按钮也有悬停、按下和忙碌反馈。卡片中的失败信息仅表示软件连接结果，不能替代现场设备状态检查。

如果连接失败，优先检查：

- 设备是否通电
- 串口号是否与 `config/system_config.yaml` 一致
- 是否有其他程序占用串口

### 2.3 加热器操作

可执行的核心操作：

- 设置目标温度
- 启动加热
- 停止加热

设置温度和启动加热前，页面会提示确认串口、温度探头、加热对象、接线和现场看护。设备未连接或后端返回失败时，页面不会显示为成功。

目标温度输入范围来自该加热器配置，上限取最大设定温度与安全限值中的较小者；范围未取得或输入越界时不提交设置，不能把固定450℃视为可用上限。

点击“断开连接”后，系统会先安全停止加热器，再释放连接。若停止命令或断开操作失败，页面会显示“连接异常”和“停止状态未确认”，并保留“重试安全断开”按钮；这不表示设备已经停止或已经断开，必须先现场确认设备状态并检查串口。

### 2.4 蠕动泵操作

单通道启动确认期间，重复点击不会再发起一次启动；提交使用确认时的参数快照。确认框仍开着时点击通道停止、全部停止、断开、急停或离开页面，将取消尚未提交的启动；已发送的动作仍须通过停止结果确认。

每个泵可按通道独立控制。当前支持 4 种模式：

- `FLOW_MODE`
- `TIME_QUANTITY`
- `TIME_SPEED`
- `QUANTITY_SPEED`

如果你只需要会用，直接在页面里选模式、填参数即可。  
如果你需要理解 YAML 字段和单位，请看 [experiment_yaml_spec.md](experiment_yaml_spec.md)。
如果你要把蠕动泵接入前驱体管路、微波入口或长管路定量输运，请先按 [system_engineering_design.md](system_engineering_design.md) 做死体积、预灌和真实流量标定。
如果你要从设备就位推进到水/替代液闭环 MVP，请按 [mvp_device_ready_runbook.md](mvp_device_ready_runbook.md) 先完成设备确认、三层液路标定和运行记录。

Heat 在软件层按 Modbus RTU 控制蠕动泵；现场物理接线可能是 RS232，也可能是设备支持的其他串口接法。界面里的 COM 口和驱动协议不等于强制要求现场一定使用 RS485。

泵管型号必须按现场实际泵管填写，不要凭示例照抄。LabSmart 泵头/软管编号表见 [device_materials/多通道蠕动泵MODBUS通信协议.md](device_materials/多通道蠕动泵MODBUS通信协议.md) 的“表 1：泵头 & 软管编号”。如果实验日志出现 `tube_model mismatch`，可能是 YAML/配置与设备设置不一致，也可能是设备固件使用了不同的读回编号；Heat 仍会阻止启动。只有在具体泵的 `tube_model_readback_overrides` 中登记、并由现场 HMI 规格确认的映射才允许继续。在确认真实泵管前，不要把流量或体积结果当作定量数据。

启动泵通道前，页面会提示确认串口、通道、模式、软管、流向、入口/出口、收集或废液容器和现场看护。停止操作仍应优先用于安全停机；如果泵设备返回失败，页面会明确显示失败。

定时定速（`TIME_SPEED`）先切换模式并设置运行时间、重复次数及本次指定的间隔，最后设置流量。启动前会重新核对全部这些参数和单位；任何写入、读取或核对失败都不会启动，控制页会显示通道、失败阶段和具体原因（`expected` 为期望值，`readback` 为设备读回值）。启动确认后还会核对模式及流量/单位，只有通过才提示成功；若不一致，会尝试停止，并明确显示“停止已确认”或“停止未确认”。停止未确认时须现场确认设备状态，不要反复点击启动。

定时定速修复的现场验收须在安全水测条件下完成：以通道 4、15 mL/min、5 分钟、重复 1 次为例，核对设备屏幕、最终寄存器和页面读回一致，并确认到时停止；运行中的剩余时间会递减。若设备拒绝在定时定速模式下设置流量，保留页面错误和协议日志供排查，不改用其他模式绕过失败。

页面按实际单位显示泵流量；`TIME_QUANTITY` 会先把体积和时间换算为 `mL/min`。输入上限取所选管型额定上限与通道配置 `max_flow_rate` 的较小值；若换算后某单位没有满足协议最小值 `0.01` 的合法区间，该单位会被禁用。实时和历史数据中的 `running` 表示启停寄存器读回，`read_ok` 表示本次读取有效。通道读取失败时页面显示“读取失败”，状态值不沿用上次读数。`flow_rate` 是设备设定/报告流速，不是独立流量计实测值；只有 `running=true` 且 `read_ok=true` 的区间才表示软件确认的输运区间。RPM 或未知单位不会与体积流量混在同一坐标轴。

每个泵通道的“预灌估算”可以录入多段软管长度。页面使用当前软管型号规格中的内径汇总理论死体积，并按当前页面设定的有效流量计算理论预灌时间；`TIME_QUANTITY` 使用体积与时间换算后的流量，RPM 模式因缺少体积流量而不计算时间。管段长度保存在当前浏览器中，但估算结果不会写入泵运行参数或实验 YAML。该结果不包含接头、反应器、气泡、管路弹性、背压和安全余量，真实操作仍须完成排气、真实流量标定和实验室确认。

### 2.5 微波仪操作

微波仪是高压、加热、微波输出设备，不能按普通加热器处理。当前页面支持连接、断开、刷新状态、配置参数、启动和停止；按 2026-06-20 用户确认，微波仪手动前端控制已像加热器/蠕动泵一样开放。页面会显示当前注册串口（本地当前为 COM6）；按钮可以点击，但未连接、状态读取失败、故障码非零、已有功率/电流输出、用户取消确认或设备返回失败时，不会显示为成功。

手动控制页采用电脑托管程序，支持自动功率、手动功率。每次打开默认 1 个逻辑段，点击“添加一段”增至最多 5 段，最后一段可以移除，至少保留 1 段。填写各段温度、到温后的保温时间及适用功率，点击“检查程序”（只校验，不写设备），再确认“启动托管程序”。参数、段数、模式或连接变化后需重新检查。刷新页面不启动程序，草稿段数恢复为 1，但会读取已有托管进度；已接受的同一启动请求不会重放。

后端逐段执行“配置 → 启动并等待物料到目标 ±1℃ → 有效保温 → 确认停止”，最后一段停止后结束。到温后在目标±3℃内累计有效保温，越界暂停累计、回温后继续；最多额外等待10分钟。段间短暂停机并重新配置，不能等同于设备原生连续多段。每个逻辑段将五个硬件段覆盖为同一目标，设备段保护时间为“到温超时＋本段保温时间＋600秒＋60秒”，启动后再读回本次配置；不使用未经确认的方案或起止段地址。设备方案与执行范围仍须现场核对。默认到温超时600秒，超时或状态/故障读取失败即停止并锁定。实际方案映射、启停及计时行为须按 [实机清单](microwave_smoke_test.md#电脑托管逻辑段验收) 确认。

微波设定温度须填写整数℃，手动托管及引导式的固定、范围和列表设置均如此；小数不会被截断或自动取整。实际测温读数仍可有小数。到温超时会显示目标、最后温度、等待时长和控制状态；原始失败原因在停机清理后仍保留。降温收取必须同时确认温度 ≤45℃、控制已关闭、输出已停止且无故障，仅瞬时功率为零不能放行。

关闭或刷新网页不停止后端程序；运行期间须保持后端服务运行并现场看护。托管程序仅支持停止，不支持暂停/继续。失败或服务重启后不会自动恢复，须先停止设备，再现场确认功率、电流归零并点击“现场确认停止后解除锁定”；停止未确认或恢复记录未保存时保持锁定。服务异常退出会失去电脑监督，不能保证立即停机，设备长计时也不代表整个程序会自主安全结束。原始 REST/YAML 与引导式批次保留各自执行方式，本托管功能不改变其段数语义。

启动微波前，页面会要求二次确认。实验室人员必须人工确认：

- 炉门已关闭。
  - 说明书/任务记录显示，炉门未关严时设备/HMI 会禁止启动并提示“门未关严”。当前通信协议没有可靠门状态寄存器，软件不会伪造 `door_closed`，仍需人工看面板和设备联锁。
- 反应瓶非空载，光纤探头已没入物料。
- 温度、功率和时间参数已核对。
- 设备运行期间有人现场看护。
- 设备电源、接地、通风和散热空间符合说明书要求。

微波仪状态字段：

实时仪表盘左侧按设备类型分组，显示数量与连接概况；切换分组不发送控制命令。温度图使用中文图例，实测为实线、设定为虚线，默认显示最近 2 分钟，可选择 1 分钟、5 分钟或本页全部数据（最多 1800 个采样点）。“暂停跟随，查看历史”冻结时间窗口，“回到实时”恢复跟随；页面关闭后不保留采样历史。服务器通信状态不代表设备已连接。超过 6 秒没有推送时状态显示未知，保留的加热器温度会置灰并明确标为旧读数，不代表当前状态；曲线保留历史，长于 6 秒的数据缺口不连线。读取失败和故障仍立即显示。微波仪显示物料温度、功率、电流、运行时间、当前段、模式及故障码。

开发服务器可访问 `/?demo=1` 查看离线温度演示，顶部始终标明模拟数据；此仪表盘数据源不请求设备接口、不建立设备 WebSocket。可点击“模拟数据中断”，6 秒后观察过期状态，再点击恢复。演示入口仅开发模式生效，生产页面不启用模拟数据。

| 字段 | 含义 |
|------|------|
| 物料温度 | 当前从设备状态读到的物料温度；浮点字序仍需实机确认 |
| 功率 | 当前实时功率百分数 |
| 电流 | 当前工作电流原始显示值 |
| 运行时间 | 由时、分、秒状态组合得到 |
| 当前段 | 当前段号，来自设备状态 |
| 当前模式 | 当前后端可识别模式；未知枚举会显示为未知 |
| 故障码 | 原始故障码；协议未确认 bit 含义前不解释成具体故障 |
| `control_active` | 40151 中协议声明可读的启动位；`null` 表示未确认 |
| `output_active` | 功率或电流是否表明存在输出 |
| `stop_confirmed` | 启动位清除且功率、电流归零 |
| `status_confirmed` | 本次控制状态读取是否有效 |

`allow_real_hardware_writes`、`enable_control_writes`、`allow_experiment_control` 仍可能出现在配置或状态 payload 中，用于兼容旧版本和现场记录；当前软件不再把它们作为前端手动或 YAML 自动控制的阻断门。真实硬件安全仍由实验室 SOP、现场看护、设备面板和设备自身门控联锁确认。

## 3. 实验执行

### 3.1 启动实验

1. 打开 `/experiment`
2. 左侧“可用实验”仅显示序号和标题，点击标题打开详情弹窗，查看说明、文件名、步骤和参数；点击“选择此实验”载入右侧操作区。浏览或关闭详情不会启动实验，也不会切换当前执行的实验；运行或暂停期间不能从弹窗选择其他实验。新增 YAML 后，点击“可用实验”右侧的“刷新”重新加载列表
3. 确认是否开启“保存日志”
4. 点击“启动”

### 3.2 实验状态说明

| 状态 | 含义 |
|------|------|
| `idle` | 当前实验未运行 |
| `running` | 正在执行步骤 |
| `paused` | 已暂停，可恢复 |
| `completed` | 全部步骤已完成 |
| `failed` | 某个步骤失败，实验中止 |
| `stopped` | 用户手动停止 |

### 3.3 单实验保护

系统同一时刻只允许一个实验处于：

- `running`
- `paused`

如果已有实验在运行或暂停，启动另一个实验会被拒绝。

## 串口稳定绑定补充

系统现在区分两个概念：

- 设备绑定身份：你希望 Heat 找到的是哪一台真实设备，例如 `SN=A6001234`、`VID:PID=1A86:7523 @ 1-3.2`
- 当前解析串口：这次启动时系统实际解析出的 `COMx`

控制页和仪表盘看到的 `connection_port` 只是本次解析结果，不再代表设备身份本身。

当你更换 USB 物理接口后：

- 如果设备绑定规则足够稳定，系统会在启动时自动把设备重新映射到新的 `COMx`
- 如果页面显示“未匹配”或“端口回退”，说明系统没有可靠找到目标设备，需要先检查绑定规则和现场接线，再尝试连接
- 如果设备是在后端启动后才被 Windows 枚举出来，控制页会在发现“未匹配”时自动请求后端重新扫描一次绑定；仍未匹配时再按下方清单排查。

优先检查：

- 设备 USB 转串口是否暴露了稳定 `serial_number`
- 是否改了 USB 集线器或物理口，导致 `location` 变化
- 多台同型号转串口设备是否同时在线，造成“多重匹配”
- `config/system_config.yaml` 中的 `connection.binding` 是否仍然对应目标设备

## 4. 行为语义

这部分非常重要，回答的是“按钮按下去以后系统到底会怎么做”。

### 4.1 停止 / 暂停 / 恢复的区别

#### 停止

- stop 会中断当前等待步骤
- 系统会停止本次实验曾尝试启动的加热器、泵通道和微波仪；全部停机确认成功后实验才结束为 `stopped`
- 任一设备停机返回 `False`、timeout 或异常时，stop 接口返回失败，实验终态为 `failed`；此时必须现场确认并按 SOP 使用设备面板或物理急停，不能把页面请求结束当作设备已停
- 如果终态仍显示“停止未确认”，页面会保留“重试停止”入口并持续刷新清理状态；确认设备安全前不要启动其他实验。
- 全局急停会先取消待执行操作并派发设备停止，不等待普通手动请求释放实验注册锁；设备仍按各自串口锁完成停止，软件不能保证物理急停响应时间。
- stop 是终止当前 run，不是临时挂起
- 全局急停只有在所有已注册设备都实际收到并确认停止命令时才返回成功；未连接、跳过或没有注册设备都会显示失败，需要现场确认或使用物理急停
- 全局急停失败时会列出每台设备的连接、尝试和停止确认结果。泵停止要求 `n001=0`；微波停止要求 40151 启动位清除且功率、电流归零。读取失败显示“状态未知”，不能解释成已经停止

#### 暂停

- pause 会让实验进入 `paused`
- 普通等待步骤会停止计时和轮询；已发出的注射泵动作及软件定时流量排液继续受监督并结束，后续步骤等待恢复
- 已经发出的同步设备命令不会被强行取消；命令返回后，引擎会停在步骤收尾处等待 resume
- 暂停后可以继续 `resume`
- 暂停不会自动把 run 改成完成或失败

#### 恢复

- resume 会从暂停状态继续执行
- 只对当前 paused 的实验有效

### 4.2 等待超时后会发生什么

如果等待条件超时，例如：

- 等温未达到目标
- 泵完成等待超时

系统会把该步骤视为失败，而不是静默继续往后执行。默认 `on_error: stop` 还会停止本实验曾尝试启动的设备；停机失败同样会保留为失败状态并要求现场处理。

### 4.3 浏览器刷新 / 关闭是否会影响设备

不会因为页面断开就自动停止设备。

浏览器刷新、关闭或 WebSocket 重连不会等同于“停止实验”或“停止泵”。  
如果你要真正停设备，请使用页面按钮或明确的控制接口。

这条规则同样适用于微波仪：WebSocket 断开不会自动停止微波输出。微波仪运行时必须由现场人员看护，并通过页面按钮、实验停止、设备 stop 或急停流程明确停机。

### 4.4 微波仪自动控制边界

按 2026-06-20 用户确认，微波仪 YAML 自动控制已开放，`microwave.configure_*`、`microwave.start` 和 `microwave.stop` 可以像加热器/蠕动泵动作一样由实验流程调用。

当前推荐把微波自动化写成“配置自动/PID 温控参数 -> 启动 -> 等待物料温度达到目标 -> Heat 外层计时保温 -> 显式停止”。不要把 `microwave_complete` 作为真实实验主流程的唯一结束条件，因为当前外控资料没有已实机确认的“程序完成”寄存器。

软件测试、页面二次确认和 YAML 结构校验不能替代实验室确认。真实运行前仍必须由实验室确认设备身份、接线、炉门联锁、非空载、探头、SOP、写入顺序和停机语义。实机验证清单见 [microwave_smoke_test.md](microwave_smoke_test.md)。

### 4.5 日志保存开关的影响

启动实验时可选择是否保存日志：

- 开启：实验日志会写入历史记录与原始日志文件
- 关闭：仍可实时看到日志，但不保存原始日志文件

### 4.6 `samples.csv`、历史记录、原始日志的关系

- `samples.csv`：面向样品追踪，记录 `sample_id`、batch、condition、状态等
- 历史记录：面向实验运行查看
- 原始日志：面向排查和还原 run 细节

它们相关，但不是同一个东西。

实验执行状态与追踪记录状态也相互独立：设备流程可以已经 `completed`，但日志文件或 `samples.csv` 仍可能因为磁盘、权限等问题写入失败。此时实验页面会显示“实验执行结束，但追踪记录失败”，历史页面会标记“记录失败”；该 run 不应被当成追踪完整的数据使用，必须先排查并补齐记录。

## 6. 历史记录与日志

删除历史会先删除关联样品行，再删除日志。文件被占用或存储失败时会明确报错并保留可重试入口；批量删除可能已有部分完成，应解除占用后重试。正常关闭服务会先等待普通实验、引导批次及微波托管程序停止并记录结果，再释放设备；强制结束进程不具备这一保证。

你可以在历史页面查看：

- 已保存的实验 run
- 运行状态
- 原始日志内容
- 单条记录详情、步骤状态与错误信息
- 实验报告曲线：加热器 PV/SV、微波仪物料温度、微波功率/电流、蠕动泵报告流量和估算累计体积

蠕动泵曲线只使用同一采样时刻、明确读取有效且运行状态已知的数据；读取失败或旧记录缺少有效性标记时保留缺口。累计体积从首个采样时刻按报告流量估算，并非外部流量计实测；遇未知采样后不再输出累计总量。RPM、单位未知或同一次记录内单位变化时不估算体积；混合单位记录保留原始数值，但不绘制可比较的流量曲线。采样间启停和未采到的输液无法据此还原。
- 日志与 `samples.csv` 的追踪记录状态；失败时显示“记录失败”

历史页面支持：

- 表格在屏幕内独立上下滚动，表头固定；横向滚动条始终位于可见的表格底边，无需滚到最后一条记录。
- 勾选多条记录后批量导出为一个 JSON 文件。
- 勾选多条记录后批量删除；删除前会弹出确认。
- 在详情中导出或删除单条记录。
- 清空全部历史记录。

删除历史记录时，系统会同步删除 `samples.csv` 中对应 `run_id` 的样品行，避免留下指向已删除原始日志的孤立记录。没有对应历史日志的样品记录不会被“清空全部历史记录”误删。

历史记录更适合回顾实验过程；`samples.csv` 更适合做样品维度的追踪。

## 8. 常见问题

### 8.1 实验为什么启动不了

常见原因：

- 已有其他实验处于运行或暂停状态
- YAML 文件名不合法
- YAML 缺少 `steps`
- 设备未连接，导致第一步立即失败

### 8.2 为什么实验一开始就失败

常见原因：

- 加热器或泵未连接
- YAML 参数不完整
- 设备命令返回失败

### 8.3 为什么页面上看不到实时数据

常见原因：

- 设备尚未连接
- WebSocket 未连上
- 页面未刷新到最新前端版本

### 8.4 为什么停止后很快就结束

这是当前设计的预期行为。  
stop 会尽快中断等待并结束实验，而不是等完整等待时间走完。

### 8.5 微波仪为什么配置或启动失败

常见原因：

- 微波仪未连接，或驱动返回失败。
- 前端读取状态失败，需要先刷新并确认设备正常。
- `fault_code` 非零，或当前功率/电流已经非零，前端会阻止重复启动。
- 设备自身门控联锁、HMI 状态或串口协议拒绝执行。
- YAML 自动控制中设备方法返回 `False`、timeout 或异常。

## MSP1-CX 注射泵

控制页新增两台独立注射泵。默认“吸排液”只显示状态、吸排量、速度、超时及吸取/排出；“设备准备”展开后可选择初始化方向和代码，首次连接后位置未确认时自动展开。“高级操作”收纳绝对定位、阀位、硬件暂停、参数、程序/I/O和诊断。停止按钮始终在设备标题旁。泵1按配置指纹绑定，泵2尚未填写串口，显示待配置。服务启动和页面生命周期不连接、初始化或运行注射泵；必须手动连接，检查安装与液路后再明确初始化。

手动与引导式初始化均只需发起一次。命令已接受且泵仍忙碌时，代码 7“设备未初始化”作为初始化尚未完成处理，继续在设定超时内等待，不重复发送初始化命令。只有空闲、无故障且零位、阀位及命令缓冲完成读回一致后才确认成功；空闲后仍报代码 7、其他故障、读取失败或超时仍按失败处理。初始化完成前位置保持未确认；现场必须核对真实运动与归零，不能仅凭命令已接受判断成功。

吸排量支持 µL/mL/步数。界面的 Hz 是电机脉冲频率；旁边的 µL/s 仅按当前注射器和步进模式估算理论活塞速度，不是实测出液速度。超出剩余行程的一侧操作会禁用。读取失败显示未知，过载或位置失信时禁止继续运动。单泵停止和全局急停不因实验占用而隐藏；停止未确认必须现场检查。实验暂停让当前动作完成，停止下发后续动作，期间继续监视故障；需要立即中断请停止实验或急停。

历史页新增位置/理论体积曲线，短动作结果直接保存在步骤记录，文本及JSON导出包含注射泵信息。软件验证通过，实机验收待进行。完整操作、参数范围与限制见 [注射泵接入说明](syringe_pump_integration.md)，后续现场按 [验收清单](syringe_pump_acceptance.md) 执行。

## 实验图形化编排

控制页的全局急停会同时终止当前实验的后续步骤调度并停止设备；急停完成后，原实验不会自动继续启动设备。任何设备或实验清理停止未确认时，页面会报告失败，仍需现场确认。实验页面按步骤 ID 显示运行与结果，禁用步骤保留展示但不占执行步骤编号。

微波完成等待遇到非零故障码会失败；输出暂时归零或状态未确认不会作为正常完成。注射泵动作到达超时时，监督程序会先读取当前状态，已经确认完成的动作不会被误报超时；读取失败时仍按未知状态处理并尝试停止。

实验自动化页面提供“新建实验”和“编辑此实验”入口，进入独立的实验编排页。左侧动作库按设备分组，中间步骤卡片按从上到下的顺序执行，右侧编辑所选动作的参数、等待条件和失败策略。支持拖动排序、复制、禁用、删除、撤销和重做；编排、校验和保存不会连接或运行设备。

实验页顶部提供默认折叠的“仪器自动化实验指南”。点击加热器、蠕动泵、微波仪、注射泵或三通阀名称，可展开该仪器的参数设置方法、编排流程与注意事项；再次点击收起。原有顶部状态条和暂停提示已整理到指南中，实时设备状态请查看仪表盘。指南不连接或控制设备，实际参数与现场操作仍按实验要求和 SOP 确认。

编排页同时提供 YAML 编辑模式。图形模式和 YAML 模式编辑同一份文档，手写 YAML 中的注释、禁用步骤、等待参数、元数据和未识别字段会尽量保留。包含锚点、别名、合并键、显式标签或多文档的复杂 YAML 只能在 YAML 模式编辑，避免图形转换改变语义。

“校验”只表示 YAML 结构和软件参数检查通过，不表示设备已连接、液路已安装或现场安全确认已经完成。保存使用文件版本检查；文件被其他进程修改、实验正在运行或停机清理未完成时不会覆盖原文件，应重新读取或使用“另存为”。保存后返回实验页面，仍需按原有确认流程明确启动实验。

## 三通阀手动控制

设备控制页左侧选择“三通阀”，点击“连接设备”读取继电器状态。显示串口及绑定身份；当前 valve1 配置 fallback COM7、转换器序列号 DU0ER6Y3A，实际端口由唯一指纹解析决定。页面加载不连接设备。

“公共口 → NO（断电）”和“公共口 → NC（通电）”在确认后切换继电器第1通道，并读取状态确认。阀线圈须接继电器 NO 触点回路；按钮中的 NO/NC 指 T 型阀的流体口：断电连通常开口 NO，通电连通常闭口 NC；此标注基于线圈接继电器 NO 回路，不是实际出口传感器反馈。现场用清水检查新阀铭牌为二位三通版本，以及两个位置对应的出口、漏液和失电流路。0127 A 是二位二通常闭版本，不能代替三通 T 版本。

读取失败或写入超时显示状态未知，不自动重复切换；使用“刷新状态”重新核对。断开通讯保持当前阀位，不切断线圈供电。三通阀两个位置均有流路连通，因此在现场尚未确定安全流路前，全局急停保持阀位并报告阀门停止未确认；不能把急停理解为关闭两个出口。系统关闭只释放该阀通讯。

### 引导式批次实验

左侧“实验自动化”提供“引导式”和“搭建式”。引导式地址为 `/experiment/batch`，按前驱体加热、进料、微波反应、产物收集、清洗排液、预充与排气和批次确认填写；搭建式保留原自由编排。固定装置为 heater1/2、syringe_pump1/2、microwave1、pump1（通道三清洗进液、通道四排液）和 valve1，不提供装置选择。

六项实验条件是 A/B 前驱体温度、A/B 进样量、微波反应温度和到温后的保温时间。支持固定值、范围间隔和指定数值；范围不补齐不在步长上的终点。独立条件全组合并计入重复次数，最多 200 组。页面显示理论进样及清洗用量、产物瓶数量和填写的抽液时长，后端重新计算组合并校验完整流程。新建批次的实验数值默认留白，单位标在输入框右侧；范围起点、终点与间隔也需填写。上一步／下一步固定显示在底部，逐页校验已填写的步骤；最终预览与启动前检查完整参数。恢复已有批次时显示保存值。

先在装置控制页连接所有设备。本入口不自动连接；每批预充前由明确确认的操作依次初始化两台注射泵，确认完成及可信零位后才开始预充。预充页可分别选择初始化方向与代码，方向默认 Z，代码按容量预选（当前 2.5 mL 为 0），须按现场验证结果核对。引导式固定 NO（断电）为产物出口、NC（通电）为废液出口，须按此映射确认实际接管；搭建式仍可自由编排 NO/NC；确认进液、排液方向以及微波负载等现场条件。点击“生成并校验完整批次”不会控制硬件；设置初始化与预充参数后直接进入批次确认，校验完整批次并勾选现场确认，点击“开始自动实验”并确认。后端自动完成初始化、预充及排液，成功并重新检查设备就绪后继续正式实验，无需单独启动预充。未连接、泵忙或读取失败、初始化错误或过载、剂量超容量、微波输出未确认停止、蠕动泵通道未确认停止或已有实验占用都会阻止启动。

每组流程：两路前驱体加热，同时在各自目标 ±3℃ 内连续保持 30 秒，才开始吸液和进料；任一路越界则重新计时，暂停后也重新计时，读温失败或无效温度立即失败；两台注射泵各自吸取剂量；两泵并行下发排液动作，等待各自完成；保持前驱体加热，微波升温并到温计时保温；停止微波；等待实测反应液温度 ≤45℃；再次检查温度 ≤45℃；切 NO 产物出口并按填写时间抽取；先切 NC 废液出口，再注清洗液、停留、按填写时间排出清洗液，按清洗次数重复；保存本组运行和样品记录，加热器保持运行，再按下一组温度调整并重新等待两路稳定 30 秒。反应、降温、清洗、组间和暂停均保温，整批结束、失败或停止才关闭加热器。并行下发不保证两台硬件在完全相同的时刻运动。

没有圆盘或自动收液装置。产物自动从三通阀产物出口排出，产物瓶更换由现场安排；程序不等待逐组换瓶确认。页面刷新或关闭不停止硬件，重新打开可读取批次状态。暂停不下发下一步骤，已发出的双泵动作继续完成并监督故障；继续不重放动作。停止会中断等待并清理已启动设备，停止未确认时显示失败并继续阻止新实验。

设置阶段右侧“本批实验”先显示“待完成设置”，完整批次校验成功后显示组数；修改参数后重新等待校验。用量与产物瓶数量收在“用量与收集准备”中。三项执行确认集中在最后的“批次确认”页：接管、泵向与微波负载；设备、容量与前驱体相容性；初始化方向、代码与预充耗液。修改任何参数（含重复次数）后，须重新校验并在此页重新勾选，无需返回预充页。启动按钮旁显示未启用的原因。页面提示先连接设备，不代表已经检测到设备连接；实际就绪状态由后端在启动时检查。NO 收产物、NC 排废液及完整启动说明保留。

启动成功后自动切换到同一页面的“实验进度”视图，集中显示整批完成组数、当前组、当前动作及设备、预充循环、各组条件与样品编号，并提供暂停、继续和停止。阶段条突出正在执行的初始化与预充、前驱体加热、进料、微波反应、降温收集或清洗；整批进度只按完成组数统计，不预测升降温或整批剩余时间。累计用时为本次预充或当前组的运行时间，包含暂停；状态每 2 秒从后端读取，读取失败明确提示显示的是上次状态。刷新页面自动恢复进度；“查看参数”只切换显示，执行中参数不可修改，页面切换不控制硬件。

产物排液时间与清洗排液时间独立填写（0.1–9999 秒），整批分别使用同一设定值，共用排液流量；初始为空白，须填写后才能执行。产物与清洗页面不展示理论排液时间，也不提供估算按钮；按现场排空效果填写时间，清洗页按进液流量／进液量、停留时间／次数、排液时间／只读排液流量排列，同步显示产物页填写的“排液流量”。清洗进液仍按每次体积÷进液流量×60 自动计算。三处排液使用 FLOW_MODE，由软件从启动确认后计时并主动停泵，停止读回确认后才完成；清洗进液仍使用 TIME_QUANTITY。时间×流量只是名义排量，不表示真实产物体积。排液时间应覆盖现场标定的管路死体积及排空余量；延长时间不能单独证明排空，须验证残留、背压和软管允许的空转条件。三通阀读回不能证明真实液路位置。旧批次记录仅供查阅，缺少新排液时间或使用 NC 收产物的旧预充不能直接复用。

产物收集页在通道四排液设置旁提示“建议流量 15 mL/min，抽液 5 分钟（300 秒）”。提示仅供填写参考，输入框仍默认留白，实际执行使用用户填写的流量和时间。

默认前驱体稳定到温超时 3600 秒、微波到温超时 600 秒、注射泵动作超时 120 秒、降温超时 3600 秒；这些值须现场验证，后端请求支持有界调整。读温失败、降温超时、双泵任一路失败、设备指令失败或记录保存失败均停止批次，不继续下一组。启动前保存完整流程快照，批次及单组记录保存在 output，单组复用 run_id、sample_id 和现有历史记录。

完成、失败或停止后，累计用时固定，不再随状态刷新增长。“停止本批次”停止整批，不是跳过当前一组。设备清理及记录保存确认后，可点击“新建实验”返回第一步，清空名称和全部实验数值，设备与方向等恢复预选；“沿用本次参数新建”只复制已保存参数，名称仍需重新填写。两种方式均重新校验、勾选确认，并在新批次重新初始化和预充，旧记录保留。若显示恢复锁定，须现场检查停止、残留及液路后点击“现场已检查，解除锁定”，再选择新建方式。

第一页“实验名称”必填，首尾空格会去除，允许1–80个字符，不含换行及控制字符，可以重名。名称显示在批次确认、进度及历史记录中：预充为“名称 · 预充”，正式组为“名称 · 第 N 组”。批次ID、运行ID及样品编号仍由系统独立生成。旧记录无名称显示“未命名实验”，不改写历史。

同一引导批次在历史中按阶段分行：`guided_<批次标识>_priming.yaml` 表示整批一次的初始化、加热与预充，`guided_<批次标识>_1.yaml` 表示第 1 组正式实验，后续组依次编号。因此一批只有一组时，正常会有两条运行记录，并非重复启动。这里的 YAML 名称是生成流程的记录标识；完整预充与各组配方保存在 `output/guided_batches/plans/<batch_id>.json` 快照中，不要求在实验文件列表里存在两个实体 YAML。各阶段通过相同 `batch_id` 关联，分别保留运行 ID 和结果；预充维护编号不作为正式产物样品用于优化反馈。可用“查看本批历史”一起查看。

新建空白实验不回填上次参数；填写期间自动保存本机草稿，刷新或从入口继续草稿可恢复输入，但须重新校验和现场确认。若存在运行、暂停或需要恢复处理的批次，优先显示该批次，不能通过新建绕过占用或恢复检查。

服务重启不会自动恢复批次。中断批次会锁定新实验启动，须现场确认所有设备已停止，再点击“现场已检查，解除锁定”解除锁定；原批次不续跑。此实现已通过软件测试，设备验收、真实液量、液路、45℃测温及停机行为仍需实验室验证。

“高级：已有模板参数设计”仍使用 `/experiment/batch/template`，保留已有 YAML 参数提取、校验和单组另存功能，与引导式执行独立。Campaign/planner 不直接控制硬件。


### 批次前驱体预充与排气

点击“开始自动实验”后，每批先自动初始化 A、B 各一次并预充一次，成功后自动继续正式实验；各组不重复初始化或预充。A/B 每次预充体积和共同循环次数默认留白，须按实验填写；先泵 1 全部吸排循环，再泵 2，全部液体先进入微波反应仪，最后切向废液端，由蠕动泵通道四排液。该阶段不启动微波：先检查反应液温度 ≤45℃，再依次初始化 A/B 并确认可信零位；按第一组目标启动两路前驱体加热，先检查两路目标 ±3℃、连续稳定30秒，再开始预充页填写的“到温后等待时间”（分钟），结束后才预充吸排。升温不计入脱气等待，暂停不计入；稳定到温等待上限独立为60分钟。前驱体持续保温；预充液进入反应仪后，排液前等待其实测温度 ≤45℃，读取失败或超时不排液。预充完成后再次确认两路稳定到温，才开始正式吸液与进料。初始化失败停止本批次，不自动重试或进液。排液后保持废液阀位，正式流程到收集时才切产物端。

页面分为“泵初始化”“预充与排气”和“可用容量”三个区域。初始化方向与代码保留预选，其余实验数值默认留白。排液时间直接填写，预充流量独立于正式产物收集和清洗排液流量。产物、清洗和预充排液字段旁均提示“建议流量 15 mL/min，抽液 5 分钟（300 秒）”，输入框默认留白，推荐值不自动填入。预充排液时间直接手动填写，不再提供估算按钮。排液时间与流量须现场标定，并覆盖死体积与排空余量。页面简洁显示耗液、废液及运行进度，流程源码默认折叠。

“可用容量”默认折叠，包含必填的反应仪可用容积、两路可用前驱体量及废液瓶剩余容量；未填写时标题显示“待填写”，校验失败自动展开。可用储液量须扣除防吸空余量；后端核对累计预充量、正式单组剂量及每次清洗液量均不超过反应仪可用容积，并核对预充加整批进料耗液及预充加整批清洗废液量。实际残留、溢流余量、废液相容性及防溢出仍需现场确认。两种前驱体必须可以混合；加热前驱体预充时的润湿、气泡和第一组残留剂量影响也必须实测验证。

预充成功后自动进入正式实验，设备始终归本批次占用。刷新页面只恢复状态，不重复初始化或预充。采用当前加热预充流程的单独预充入口留下的“待正式启动”批次可沿用（此前冷预充结果仅供查看）：参数不变时，重新校验并勾选确认后点击“开始自动实验”，不会重复预充。更改参数会使原结果无法用于启动，请先停止旧批次再重新准备。停止正在预充的流程、预充失败或服务中断后，现场检查残留和液路并确认设备停止，再解除恢复锁定；不自动重试或从中途恢复。阀切换只取消未执行的操作，不自动换到另一个出口。

旧批次记录仍可查看；旧余量系数及附加时间按原公式恢复排液时间、旧抽液流量恢复为预充流量，仅供展示，不重新取得预充执行资格。

### 引导式保温监督与暂停

保温分钟必须能转换为整秒（例如0.5分钟为30秒），不能截断小数秒。每组先将五个硬件段配置为本组目标并读回，启动后再核对本次参数块；不一致或读取失败则停机清理，不自动重启。设备段保护时间为“到温超时向上取整秒＋本组保温秒数＋600秒＋60秒”。例如80℃、保温10分钟、到温超时10分钟时，五段均设80℃及31分钟；电脑在80±1℃到温后，累计80±3℃内的10分钟有效保温，越界暂停累计、回温后继续，最多额外等待10分钟，完成后显式停机。参数读回不能证明本机实际方案，仍须现场核对。

进度显示有效保温X/Y秒、当前温度与目标范围、已等待时间及上限。故障、无效读数、状态未知、通讯预算超限或控制位退出均失败，截止附近不保留1秒宽限；功率暂时为零不会单独触发故障。失败后不抽液、不开始下一组。日志保留配置实读、启动核对、温度来源和停止来源，现场恢复事项仍须处理。

微波启动后点击“暂停批次”，页面显示“当前反应继续，结束后暂停”。升温、保温及故障监督继续；反应结束并确认微波停止后显示“已实际暂停”，不抽液、不进入下一组。可以取消尚未落实的暂停请求；实际暂停后继续不会重复进料或反应。需要立即中断时点击“停止本批次”。通道四排液期间暂停不延长当前排液，到时停泵后等待继续；其他阶段保留原暂停语义。

预览、预充启动和正式启动都检查固定设备/通道是否启用，预充排液、产物排液和清洗进液的流量不得超出通道配置上限。容量须由现场扣除必要余量后填写；每次清洗液量也不得超出反应仪可用容积。错误在消耗前驱体之前报告。

预充保留维护日志和 samples.csv 条目，编号为 `{batch_id}_PRIMING_{run_id}`，正式产物按组使用 `S001、S002…`。旧编号、旧记录及表征关联不重新编号。引导批次占用设备期间允许保存其他 YAML；执行中或待清理的同名 YAML 仍禁止覆盖。

软件回归不等于设备验收。真实微波到温与有效保温计时、截止附近退出和通信延迟、短泵启动读回、45℃降温与停机须由实验室验证；完成读回不能证明液量准确或已排空。

预充页“到温后等待时间”必填，初始留白，范围0–1440分钟且须可换算为整秒；填0仅取消额外脱气等待，仍须稳定到温。该等待每批一次，前驱体加热持续至整批结束（失败或停止仍停机）。旧批次缺少此参数时仅供查看，重新填写并校验后才能创建新批次。


### 排液分区与设备连接

清洗页将“清洗进液 · 通道三”和“清洗排液 · 通道四”分开显示。进液区设置流量、每次液量、停留时间、清洗次数及方向；排液区填写时间，并显示沿用的产物排液流量。流程仍为切 NC → 进液 → 停留 → 排液，按次数重复。

设备控制页各设备卡片右上方统一提供“连接设备”或“断开连接”；窄屏时显示在标题下方。断开仍沿用各设备原有处理，加热器会安全停止后断开，三通阀保持当前阀位。

页面顶部“一键连接全部设备”按加热器、蠕动泵、微波仪、注射泵、三通阀依次连接，已连接设备跳过，未配置或串口未匹配设备列出原因。失败后继续其他设备，完成后逐台显示结果；再次点击可重试未连接设备。连接成功但读取失败会显示“已连接，状态未知”，不代表设备已就绪。

连接期间禁止重复连接或断开；实验占用拒绝会停止后续连接。点击急停或离开控制页会取消尚未发出的连接请求，当前请求仍需结束。一键连接只建立通信并读取状态，初始化及实验启动仍按各自操作流程执行。

### 引导式进度与结果（2026-10-16）

启动后，“当前动作”位于进度区上方，显示动作说明、相关设备及已有读数。六个阶段使用图标与文字：当前阶段为蓝色，完成显示勾选，暂停为暂停标记，失败为错误标记；初始化与预充整批只显示一次，下一组其余阶段重新判断。

- 稳定到温显示 A/B 实际温度、目标及连续稳定秒数。越界或实际暂停后稳定时间清零；升温、降温不预测结束时间。
- 加热脱气、微波保温与清洗停留显示有效计时，暂停扣时。泵显示“设定时长参考剩余”，从启动确认计时；已发出的动作不会因页面暂停而冻结计时。参考到零只表示等待设备完成确认。
- 状态每 2 秒更新；读取失败或超过 6 秒未成功更新会标为过期。旧记录只显示已有信息。结束后保留最后动作快照，正在停止、正在清理与清理未确认分别提示。
- 暂停、继续、停止显示请求反馈。“已请求暂停，等待当前反应结束”与“已暂停”不同。网络异常显示“结果未确认”，通过刷新核对，不自动重发。暂停/继续处理中仍可停止本批次。
- 校验会返回首个错误所在页面、展开所需容量区域并聚焦字段，保留已填参数。设备或跨字段问题在页面提示。
- 已完成组默认折叠，可“展开全部”或“定位当前组”。结果区显示完成、失败、未执行组数及保存/恢复状态。“查看本批历史”包含预充及正式组；“导出本批记录”生成 JSON，缺失记录、读取失败或保存失败时明确报错，不导出不完整结果。

以上为软件状态展示，不替代现场设备及液路检查。


### 引导式排液使用流量模式

产物收集、清洗排液和预充排液均使用蠕动泵通道四的**流量模式**。例如填写 15 mL/min、300 秒：泵按 15 mL/min 运行，软件从启动确认后计时，300 秒后发出停止并确认结果。产物与清洗共用流量、分别设置时间，预充流量与时间独立；通道三清洗进液仍按设置液量执行。

排液中暂停不会延长本次抽液：泵继续到设定时间后停止，后续步骤等待继续；“停止本批次”会提前终止排液。读取失败、提前停机或停止未确认会中止流程并提示恢复处理，不能据计时归零判定已停止或排空。软件定时依赖控制电脑和后端运行，后端退出、电脑掉电或通信中断时不能保证泵自动到时停止，须现场停机。使用前按水测核对实际流量、到时停止、暂停和异常停止。

引导式进度温度显示保留一位小数，控制判断及记录保留原始精度。微波保温提前退出时停止本批次，报错包含已保温/剩余秒数及设备状态；不能以温度仍在目标附近替代控制状态确认。2026-10-19 水测排查见 [水测记录](water_test_microwave_20261019.md)。

注射泵手动吸排液面板的初始吸排量为 2.5 mL，可在操作前修改；默认值不会自动执行动作，实际可吸取或排出的量仍受当前位置、容量和零位可信状态限制。

微波仪控制页顶部显示物料温度、功率和电流，串口、绑定信息、硬件当前段及刷新入口收纳在“设备详情与通信状态”。模式分为自动功率和手动功率，默认一段，可添加至五段；检查程序只校验参数，不启动设备。启动程序沿用电脑托管流程，段间确认停机，运行期间保持服务运行并现场看护。未连接或没有有效故障读数时显示“故障状态未知”，不将缺失读数解释为故障码零。

### 引导式实验入口、草稿与批次归档

进入 `/experiment/batch` 先选择“新建实验”或“历史实验”。本机有草稿时可“继续填写草稿”；新建空白实验会先询问是否替换草稿。运行中、预充就绪、待恢复、待清理或保存失败的批次提供醒目的处理入口，不允许绕过锁定开始新批次。

新实验的名称、填写参数与当前步骤自动保存到当前浏览器本机存储。短暂切页后返回入口点击“继续填写草稿”，或刷新正在填写的页面，均可继续。草稿不跨电脑同步，清理浏览器数据会清除草稿；存储失败会提示。恢复草稿不恢复校验、现场确认、启动或预充资格；旧终态批次不覆盖新草稿。明确启动成功后清除该草稿。

“历史实验”以批次列出名称、状态、时间和组数，每批详情包含原始请求参数、本批预充、各组执行结果、日志关联及完整流程快照。预充失败、正式组未开始的批次也保留详情。记录通过批次 ID、预充及各组 run_id 关联，不通过同名实验猜测；“查看记录详情与曲线”打开本批日志。“导出整批记录”将批次检查点、完整流程快照和已关联预充/正式组执行日志放在同一个 JSON 中。缺失或保存失败的日志、缺失或不匹配的流程快照会阻止完整导出并提示，不把不完整记录称为成功归档。历史查看和草稿恢复均不操作设备。

引导式实验设置页仅保留本流程的导航和“返回实验入口”，不再提供“自由编排”及“高级：已有模板参数设计”跳转按钮。

### 设备控制页布局

设备控制页的全局停止区域与设备分组在宽屏滚动时保持可见。设备标题保留连接状态及连接操作，串口与绑定信息可展开“设备详情”查看。蠕动泵通道按可用宽度并排排列，模式、软管、流量、方向、时间及体积均有独立标签；参数区为待下发设置，通道标题为当前读回状态，启动后才执行设置。各通道停止与整泵停止保持独立入口。加热器显示有效实时温度、设定温度读回和输出功率，“待设温度”须点击写入才下发。两台加热器和注射泵仅在足够宽的工作区并排显示。注射泵的理论体积与位置可信状态、初始化及高级操作保留。三通阀流路示意仅依据继电器读回推定，未知状态不显示为已确认出口，实际流路须现场核对。上述布局调整不改变设备动作、限值、初始化和停止语义。

只读监控页保留15秒数据过期窗口，以覆盖整包设备采集周期；连接关闭立即标记通信中断。过期温度以灰色保留上次读数并注明当前状态未知，曲线关闭更新动画。设备控制仍使用6秒过期保护。
