# Heat 项目开发规则

## 1. 核心原则

### 1.1 上下文优先

- 新对话开始时**必须先读 `context/PROJECT_CONTEXT.md`**
- 项目详情、架构、编码规范、设备参数均以 PROJECT_CONTEXT.md 为准
- 本规则文件仅定义**跨项目通用的行为准则**，不重复上下文内容

### 1.2 安全优先

- 硬件操作必须检查连接状态和返回值
- 关键操作（启动/停止）必须有错误处理
- 所有设备必须支持紧急停止
- 不确定的操作先问用户，禁止猜测

### 1.3 稳定优先

- 优先选择改动小、风险低的方案
- 禁止过度设计
- 代码必须可编译、可运行

## 2. 开发流程

### 2.1 任务执行

1. **分析**：理解需求，拆解任务，识别风险点
2. **开发**：按 PROJECT_CONTEXT.md 规范编写代码
3. **验证**：编译通过（Python: `py_compile`，前端: `vue-tsc --noEmit`）
4. **自检**：使用 `code-review` Skill 检查代码质量
5. **文档**：如有用户可见变更，使用 `doc-sync` Skill 更新文档

简单任务（修typo、改变量名）可跳过分析阶段。

### 2.2 命令

| 命令 | 行为 |
|------|------|
| `/review` | 使用 `code-review` Skill 审查代码 |
| `/git` | 编译验证 → 更新文档 → 提交 → 用户确认后推送 |
| `/finish` | 自检 → 更新文档 → 归档变更记录 |

## 3. 质量要求

### 3.1 代码

- 修改后必须编译验证
- 错误处理、日志、状态校验不可省略
- 资源（线程、串口、文件）必须确保释放

### 3.2 文档

- 功能变更后更新 PROJECT_CONTEXT.md
- 用户可见变更更新 user_guide.md
- API/参数变更更新 developer_guide.md
- 重大功能更新 README.md

### 3.3 Git

- 提交格式：`feat:/fix:/docs:/refactor:` + 简述
- 推送前必须用户确认
- 推送至 Gitee + GitHub 双远程

## 4. AI 行为准则

- 需求模糊时主动追问，不猜测
- 不确定时标注"需确认"
- 先验证问题存在再修复
- 新对话必须先读 PROJECT_CONTEXT.md
- 代码修改后执行自检清单
